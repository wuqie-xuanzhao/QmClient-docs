QmClient 网络卡顿与性能监控现状

本页把旧“网络卡顿诊断 + 性能监控面板”报告改成当前实现说明。核心实现是 CQmMonitoring、TClient 状态栏高密度条目、QmClient debug graph 设置，以及 qm_perf_* 性能日志链。

① 当前结论

网络卡顿可视化已经有实装主体：CQmMonitoring 每秒约 20 次采样网络和性能指标，维护 180 个历史样本，生成 SQmMonitoringSnapshot，并在 dbg_graphs 打开时渲染诊断面板。

它可以区分连接等级、主因类别、网络历史曲线、FPS/游戏时间边距曲线、实时指标卡片和调试细项。TClient 状态栏还可以把同一套快照压缩成常驻条目。

它仍不是“服务器卡顿 vs 客户端卡顿”的最终裁判。客户端只能基于本机观测和网络统计推断；公共服务器的服务端帧耗时、队列拥塞等权威信号不在当前客户端实现内。

③ 诊断规则

当前连接等级是四档：NORMAL、ELEVATED、SEVERE、DISCONNECTED。阈值写在 QmDetermineConnectionGrade() 中：未连接直接 disconnected；抖动达到 25ms、snapshot/prediction 延迟达到 180ms 或连接问题会进入 severe；抖动达到 10ms、延迟达到 90ms 或带连接问题的较高丢包会进入 elevated。

主因分类是：DOWNSTREAM、UPSTREAM、JITTER、PACKET_LOSS、CLIENT_PERFORMANCE。规则优先级会先看明显丢包和抖动，再看 snapshot/prediction 延迟差，正常连接下如果 frame time、CPU 或 prediction stress 明显异常，则归到客户端性能。

这些 helper 有单测覆盖，包括等级阈值、主因优先级、丢包估计、rollback、峰值选择、UI scale 和 panel opacity。

④ UI 与入口

  • CGameClient::RenderQmMonitoringHud() 只有在 dbg_graphs 打开时渲染面板。
  • QmClient 设置页的 Debug graph 模块提供全局按键绑定行，命令是 toggle dbg_graphs 0 1。
  • 同一模块提供 qm_monitoring_hud_opacity 面板透明度配置。
  • 面板布局由 QmComputeMonitoringHudLayout() 和 QmComputeMonitoringBodyLayout() 计算，会按屏幕尺寸和可用高度缩放。
  • 面板区域包括 header、主网络图、FPS/游戏时间边距图、8 个主指标卡片和 debug details。

因此它当前更像开发者/高阶玩家诊断面板，不是普通用户默认会看到的 HUD 提醒。

⑥ 性能日志边界

  • qm_perf_debug、qm_perf_logfile、qm_perf_debug_threshold_ms 是性能日志链的主要配置。
  • CQmMonitoring 在 QmPerfEnabled() 时会采集并输出 perf/device 设备采样 payload。
  • 设置页、资源页、TClient 页等 perf/* 日志主要用于 UI/资源/文本/帧时间归因。
  • qmclient_scripts/perf/ 的 HTML 报表可分析设置页/资源页等性能数据，但不等同于网络质量诊断面板。

⑦ 旧文档修正点

  • 旧文档里“仍需逐文件复核 Qm monitoring 组件”的保守表述已过时；当前 CQmMonitoring 已有明确实现和测试。
  • “GPU 没有进入持续监控面板”不再准确；当前 snapshot 有 GPU/VRAM/disk 字段，但设备采样受 QmPerfEnabled() 控制，平台能力也可能不同。
  • “丢包率已接入”必须补充限定：当前是 resend-based packet loss estimate，不是底层真实丢包计数。
  • “普通用户默认能看到诊断”不成立；主面板受 dbg_graphs 控制，状态栏高级项也不在默认 scheme 中。
  • 不要把设置页性能 HTML 报表和网络卡顿诊断面板混为一体；它们共享性能观测方向，但服务不同问题域。

QmUi 运行时现状

QmUi 是当前 C++ 客户端内的渐进式 UI 运行时和组件原语集合。它提供动画、布局、token/theme、旧 UI 桥接和 dogfood 组件库入口，但不是 Rust/egui 双轨 UI，也不是全局替换 DDNet 旧 CUIRect UI 的完成态。

当前结论

能力状态维护口径
QmUi runtime已接入CGameClient 持有 CUiRuntimeV2，每帧推进 tree、animation runtime 和 render bridge，并写入 perf 日志。
动画运行时已接入支持 tween/spring、delay、priority、replace/queue/keep higher/merge target、完成事件和用户 motion level。
布局引擎已实现支持 row/column、auto/px/percent/flex、padding、gap、align、justify、min/max 约束。
渲染桥统计桥CUiV2RenderBridge 当前只记录 draw calls 和 clip pushes，不是独立渲染器。
共享 widget 原语已有 dogfood按钮、表单、导航、容器、tooltip/modal/toast 等原语存在，并可通过 dbg_qm_ui_dogfood 覆盖 QmClient 设置页验证。
全局 UI 迁移渐进中菜单、HUD、计分板、名字板等多处读取 runtime 或 qm_new_ui，但不能推导为所有 UI 已迁移到 QmUi。

运行时边界

CUiRuntimeV2::OnRender() 是当前运行时总入口。每帧会 clamp RenderFrameTime() 到最多 1/15s，随后按顺序执行 m_Tree.BeginFrame()、m_AnimRuntime.Advance(Dt)、m_RenderBridge.BeginFrame()、m_Tree.EndFrame()，并记录节点数、动画数和耗时。

对象当前职责边界
CUiRuntimeV2聚合 tree/layout/anim/render bridge，并暴露 AnimRuntime() 给页面使用。运行时本身不绘制完整 UI，只推进状态和 telemetry。
CUiV2Tree记录帧内节点统计。当前文档只把它作为 runtime 内部统计能力，不写成可视化树编辑器。
CUiV2LayoutEngine计算布局盒子和子项分配。输出仍经常回到旧 CUIRect 绘制体系。
CUiV2AnimationRuntime管理属性值缓存、活动 track、队列和完成事件。受 qm_ui_motion_level 控制，motion level 0 会关闭/压缩动效。
CUiV2RenderBridge重置并累计渲染统计。不拥有 renderer，不替代 IGraphics / CUi。

目录与模块

旧文档说 QmUi 只有 6 个模块已经过时。当前目录包含 runtime、动画、布局、树、渲染统计、legacy adapter、context、设计 token、theme、按钮/表单/导航/容器/覆盖层和 dogfood 页面。

类别代表文件当前职责
运行时核心QmRt.*、QmTree.*、QmRender.*帧级 runtime、tree 统计、render bridge 统计。
布局与动画QmLayout.*、QmAnim.*、QmAnimResolve.*、QmMotion.h、QmAnimCurves.hFlex 风格布局、动画请求、属性解析、motion level 和曲线/弹簧 preset。
旧 UI 桥接QmLegacy.*、UiContext.hSUiLayoutBox 与 CUIRect 互转，以及向 widget 注入 UI/menus/tooltips/text/icon/anim 依赖。
组件原语UiButtons.*、UiForms.*、UiNavigation.*、UiContainers.h、UiOverlays.hPrimary/secondary/icon button、text field、toggle、slider、tab bar、list item、card、tooltip、modal、toast。
设计系统UiTokens.h、QmTheme.h颜色、spacing、radius、elevation、font、IME token、motion token 和 icon/IME theme。
验证入口UiDogfood.*通过 dogfood 页面集中展示并验证共享 widget 原语和缩放行为。

实际接入

  • CGameClient 在初始化时调用 m_UiRuntimeV2.Init(this)，重置时调用 Reset()，渲染阶段调用 OnRender()。
  • HUD、菜单、计分板、名字板、触控编辑等页面多处直接取 GameClient()->UiRuntimeV2()->AnimRuntime()。
  • qm_new_ui 默认开启，用于选择新版菜单/设置页样式；qm_ui_color 和 qm_ui_opacity 参与菜单颜色/透明度。
  • dbg_qm_ui_dogfood 开启时，QmClient 设置页会被 widget gallery 接管，用于验证 tokens、按钮、输入、toggle、slider、tab、list、modal、tooltip 和 toast。
  • QmUi runtime 的 perf context 会跟随当前 QmClient 设置页/操作上下文写入 perf/ui_runtime 和 perf/qmclient 日志。

这里的接入是“页面渐进使用 runtime 与 widget 原语”，不是“所有菜单都改成 QmUi declarative tree”。后续文档不能从目录存在推导功能完成。

Token / Theme

旧文档“没有统一 UI 主题/样式系统”的判断需要改写：当前已有 UiTokens.h 和 QmTheme.h，但它们更像共享常量和轻量 theme，而不是完整设计系统或 CSS-like style cascade。

层级当前内容边界
颜色surface、accent、text、success/warning/danger、IME light/dark token。仍有大量旧配置变量和页面局部颜色逻辑并存。
尺寸spacing、radius、elevation、font、IME 尺寸。值是未缩放 token，调用方仍需按 UiScale/LG 体系处理响应式。
动效motion token 绑定 ui_curve 和 ui_spring preset。最终动效强度受 qm_ui_motion_level 运行时配置裁剪。
Themeqm_theme::ICON、IME_LIGHT、IME_DARK、ImeTheme(bool)。不是全局换肤系统，不负责所有菜单颜色。

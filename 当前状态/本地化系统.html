① 边界

本页讨论的是 UI 文案本地化：Localize、Localizable、控制台 Register help 文本、运行时 data/languages/*.txt 生成和 TOML 维护源。它不讨论聊天内容翻译、LLM 翻译后端或聊天输入框翻译按钮。

聊天自然语言翻译见 翻译系统.html；聊天输入框旁翻译按钮见 聊天翻译按钮.html。

③ 常规工作流

修改 UI 文案或 TOML 后

  • python qmclient_scripts/languages_qmclient/extract_strings.py
  • python qmclient_scripts/languages_qmclient/generate_all.py
  • python qmclient_scripts/languages_qmclient/validate.py
  • python qmclient_scripts/languages_qmclient/review_duplicate_entries.py --show-groups 0 --show-unused 0

新增英文 source key 后

  • 先运行 extract_strings.py，让 active key 列表更新。
  • 使用 translate_with_local_http.py --languages ... --base-url ... --model ... --resume 生成 draft。
  • 人工审核 translations_draft/<language>/*.toml，确认没有提示词泄漏、错语言、占位符损坏、术语漂移。
  • 审核通过后才使用 translate_with_local_http.py --languages ... --write-back --resume 回填维护源。
  • 回填后重新运行 generate_all.py、validate.py 和重复项审查。

语言脚本单测入口是 python -m unittest discover qmclient_scripts/languages_qmclient/tests -v。

④ 脚本职责

脚本职责
extract_strings.py从 src/ 提取 active 英文 source keys，写出 extracted_strings.txt 和 extracted_audit_report.json。
generate_all.py根据 active keys 和 translations/i18n/*.toml 生成登记语言的运行时文件。
validate.py校验提取结果新鲜度、生成语言文件覆盖、模块化 TOML 可读性、legacy overlay 删除状态和 blocking audit violations。
review_duplicate_entries.py只读报告重复、相似、空译文和疑似未使用项，用于人工清理。
translate_with_local_http.py调用 OpenAI-compatible /chat/completions HTTP 服务生成 draft；审核通过后可显式回填 TOML。
normalize_simplified_chinese.py规范简中文案排版；不替代人工语义审核。

⑤ 旧文档修正点

  • 不要继续建议手工维护 data/languages/*.txt；需要改译文时改 translations/i18n/*.toml，再重新生成。
  • 不要把旧覆盖率数字作为当前事实引用；覆盖和缺失状态必须以最新 validate.py / 审查脚本输出为准。
  • 不要把聊天翻译后端、出站翻译按钮和 UI 本地化混为一个系统；它们共享“翻译”字样，但代码路径和维护流程不同。
  • 不要把 draft 当真相源；draft 只是候选结果，必须审核占位符、语言、术语和提示词泄漏后才回填。
  • 旧的“中文 source key 迁移”脚本只适合清理遗留或新引入的中文 key，不是日常新增文案路线。

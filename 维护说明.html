权威入口

区域当前状态维护规则
当前状态/当前说明只放当前代码现状页。改动事实前必须复核源码、脚本或 gate 入口。
规划/规划路由只说明后续可以做什么。进入开发前必须重新写小规格或计划。
调研/调研状态记录已复核的调研结论和风险，不替代源码阅读。
工作流参考/历史参考索引 `docs/superpowers/`，只用于理解背景和旧工作流，不能直接作为当前事实。
归档/历史材料已知过时或被 HTML 接管，不可直接作为实现依据。

命名规则

  • 目录和人读的页面文件名使用中文，例如 当前状态/翻译系统.html。
  • 技术名可保留原文，例如 QmUi、BindWheel、HarmonyOS。
  • 不要再用 *-status.html、*-spec.html 表达状态；状态写进页面头部元信息。
  • 共享样式只维护 assets/wiki.css，新增页面不要复制内联 CSS。

归档口径

  • 归档/已替代-当前状态/ 保存从当前说明迁出的 Markdown，当前事实以对应 HTML 为准。
  • 归档/已替代-规划/ 保存旧方案稿，只能用来追溯想法来源。
  • 归档/已替代-调研/ 保存旧调研原文，引用前必须先读对应 HTML 状态页。
  • 明显过时、错误或不再适用的旧报告保留在 归档/ 根部或专题子目录。

后续维护流程

  • 新增当前事实：先读源码或脚本，再更新 当前状态/*.html 或 调研/*.html。
  • 新增规划：先连接到 规划/index.html，并明确它不是实现计划。
  • 新增 HTML：使用 wiki 布局和 assets/wiki.css，保证相对链接可检查。
  • 引用 docs/superpowers/：只加到 工作流参考/，并标注需要按当前代码复核。
  • 完成文档改动后运行 HTML 相对链接检查和 python qmclient_scripts/gate/check_docs.py。

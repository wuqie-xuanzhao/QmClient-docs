Skin Frankenstein 可编辑配方小规格

本页把新版 TODO 中的皮肤/资源编辑器想法收敛为一个后续可开发的小闭环：在现有 Frankenstein 拖拽、染色、预览和标准 skin/skins7 导出基础上，增加可再次打开继续编辑的 sidecar recipe。

① 目标与非目标 ② 存储边界 ③ Recipe 草案 ④ 工作流 ⑤ 验收 ⑥ 当前证据

① 目标与非目标

类型范围理由
目标导出 skin 时可选保存一个 QmClient recipe sidecar。当前导出产物是标准 PNG/JSON，无法恢复每个部件来自哪个 donor。
目标从 recipe 重新打开 Frankenstein 编辑器，并恢复 slot、来源资源和 tint。让一次性编辑变成可继续维护的制作流程。
目标标准 skin/skins7 产物继续保持 DDNet/QmClient 可加载。Recipe 是编辑元数据，不是运行时皮肤协议。
暂不做分享码、Workshop 上传、资源市场、跨客户端在线同步。这些涉及兼容、版权、远端服务和安全边界，应另写调研。
禁止把 qmclient_profiles.cfg 改成部件配方存储。Tee profile 只保存皮肤名、颜色、表情、名字等运行时选择，不应承载编辑器内部结构。

② 存储边界

P1 建议使用独立 sidecar，而不是改 skins7/<name>.json。标准 skin JSON 属于运行时可加载格式，recipe 属于 QmClient 编辑器元数据。

路径用途是否标准运行时依赖
skins/<name>.png当前标准 0.6 skin 导出。是
skins7/body|feet|hands/<name>.png当前标准 0.7 skin part 导出。是
skins7/<name>.json当前标准 0.7 skin part 引用。是
qmclient/skin_recipes/<name>.json建议新增：Frankenstein 编辑 recipe。否
  • 没有 recipe 时，已导出的 skin 仍可正常使用，只是不能恢复 donor/slot 历史。
  • Recipe 文件缺失、过期或引用资源不存在时，编辑器应提示缺失项，并尽量打开可恢复部分。
  • Recipe 不应该自动上传，也不应该成为服务器或 demo 的可见协议数据。

③ Recipe 草案

{
  "schema": "qmclient.skin_frankenstein_recipe.v1",
  "name": "my_mix",
  "created_at_local": "2026-06-16T23:30:00+08:00",
  "export": {
    "skin06": "skins/my_mix.png",
    "skin7": "skins7/my_mix.json"
  },
  "canvas": {
    "type": "skin",
    "width": 256,
    "height": 128
  },
  "slots": [
    {
      "slot": "body",
      "source_asset": "skins/default.png",
      "source_rect": [0, 0, 96, 64],
      "target_rect": [0, 0, 96, 64],
      "tint": "#ffffff",
      "blend_mode": "normal"
    }
  ]
}
字段要求备注
schema固定字符串，后续变更升版本。避免旧 recipe 被新编辑器误读。
name导出名，做路径清理。应和导出产物名一致或可解释。
slots[].slot使用编辑器已知 slot ID。不要保存 UI 坐标名，而要保存稳定语义。
source_asset保存相对存储路径或资源 ID。引用缺失时允许用户重新指定 donor。
tint保存编辑器 tint 颜色。P1 不要求支持复杂图层或多重 blend stack。

④ 工作流

  • 用户在现有 Skin 资产编辑器中完成 donor -> Frankenstein 拖拽、染色和预览。
  • 点击 Export 时继续生成标准 skin/skins7 产物；如果启用 recipe 保存，同时写 qmclient/skin_recipes/<name>.json。
  • 编辑器新增“Open recipe”或在导出列表中检测同名 recipe，打开后恢复 slot 状态。
  • 导入 recipe 时先验证 schema 和路径，不符合时显示错误，不覆盖当前编辑状态。
  • 重新导出同名 skin 时，可以覆盖标准产物和 recipe；覆盖确认沿用当前导出名/未保存变更口径。

⑤ 验收

检查项验收标准
兼容关闭 recipe 保存时，现有 Skin 导出行为不变。
保存启用后导出标准 skin/skins7，同时生成 schema 为 v1 的 recipe。
恢复打开 recipe 后恢复 donor slot、target slot、tint，并能再次导出。
缺失资源引用 donor 不存在时不崩溃，提示缺失并允许用户重新指定或跳过 slot。
回归标准 skin 列表刷新、Tee profile、Skin Queue 不依赖 recipe，也不被 recipe 缺失影响。
验证记录实现后回填 皮肤混搭状态.html 和 创新路线图.html。

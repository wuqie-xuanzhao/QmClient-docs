QmClient 创新功能候选路由

本页综合新版 TODO PDF、候选 backlog 路由和当前 HTML 状态页，筛选“值得继续产品化”的创新功能方向。它不是实施计划；任何条目进入开发前，都必须重新读源码并写小范围规格。

① 筛选规则 ② 近期可产品化 ③ 中期创新方向 ④ 先调研再决定 ⑤ 默认不做 ⑥ 下一批规格队列 ⑦ 证据线索

① 筛选规则

“创新性”不等于“大范围重写”。优先选择已经有代码基础、能改善 QmClient 特色体验、又不触碰协议/物理/预测/格式兼容红线的功能。

等级判定标准推进方式
近期可产品化已有实现基础或高可信现状页，主要工作是补 UI、导出、状态、文档或小范围数据结构。直接写小规格，目标控制在一个功能闭环内。
中期创新方向体验价值明显，但涉及多个模块或需要新的持久化/同步边界。先做规格和兼容性审查，再分阶段实现。
先调研/默认不做触碰预测、协议、服务端、账号、上传审核、隐私或玩法公平性。先写调研，不直接开发。

② 近期可产品化

方向创新点当前基础下一步规格
F1/聊天导出工作流把控制台聊天筛选导出做成面向分享/复盘的工具，而不是隐藏命令。聊天F1导出状态.html：已有 TXT/HTML/PNG 导出。补 JSON/TOML、导出进度、超大 backlog 分帧和文件命名规则。
资源页 Workshop 体验收口统一本地/Workshop 资源展示、下载状态、作者、分类和预览调度，形成 QmClient 资源中心。资源页.html：10 个资源 tab、注册表、preview scheduler 已存在。先做“已下载/未下载 tag + 作者展示 + 错误状态”小规格；见 资源工坊状态.html，上传另行调研。
截图管理与水印把截图从“保存文件”提升到游戏内浏览、命名、标注和分享前处理。截图管理状态.html：已有 Screenshots 模式和截图动画。先做 水印/地图名命名，不做自动上传。
聊天输入体验增强围绕翻译、复制、草稿、右键菜单和输入反馈形成 QmClient 聊天增强体验。聊天UI状态.html、聊天翻译按钮.html。先做 输入框视觉反馈和消息行 hover 反馈，不迁移整个聊天渲染。
皮肤/资源编辑器文档化与配方把已有 Frankenstein 编辑能力变成可继续编辑的资源制作流程。皮肤混搭状态.html：已有部件拖拽、染色、预览和导出。先定义 可编辑配方边界；分享码、Workshop 上传后置。

③ 中期创新方向

方向价值主要风险入口
Demo/观战导演工具服务视频制作、复盘和观战体验，是 QmClient 差异化强项。全地图录制范围、demo 格式、自动高光评分和性能成本。Demo观战状态.html
本地跨局统计历史把 statboard、CSV、PlayerStats HUD 和中心服 playtime 统一成玩家复盘视角。数据模型、隐私、存储增长和 UI 查询性能。持久统计状态.html
收藏/资源浏览增强把地图收藏、服务器收藏、备注、标签和本地存档联动，做成重复游玩入口。DDNet favorite group 兼容、sidecar 元数据和通知边界。收藏浏览状态.html、服务器收藏状态.html
无障碍/可读性模式不是单个按钮，而是面向色弱、高对比、字体大小和焦点可见性的体验层。全局 UI 缩放、颜色语义、控件焦点和旧 CUI 布局稳定性。无障碍状态.html
网络诊断状态栏预设把已有 QmMonitoring 指标变成玩家能一键打开的诊断视图，而不是只藏在 dbg_graphs 和手写状态栏 scheme 中。不能自动修改 AntiPing 或预测参数；resend loss 和 connection quality 必须标明只是客户端观察。网络诊断面板.html
BindChat/BindWheel 产品化把高级命令绑定变成可发现、可管理、可备份的玩家工具。DDNet 原生 bind、TClient bindchat 和 bindwheel 的数据边界；不能扩成宏、脚本或自动玩法平台。绑定系统.html、绑定系统化边界.html、BindWheel快速设置.html

④ 先调研再决定

  • 品牌化迁移：当前边界见 品牌迁移边界.html；用户可见 QmClient 文案可以审计，但 Q1menG 内部识别链路、配置脚本名和远端服务路径不能做全局替换。
  • 资源上传/分享市场：需要远端服务、权限、审核、缓存和安全边界，不能从资源页 UI 直接扩展；边界见 工坊上传边界.html。
  • 自适应 AntiPing 自动调参：涉及预测体验和玩家手感，默认只做诊断建议；入口见 自适应AntiPing状态.html。
  • 完整插件平台：已有 ChaiScript 手动执行能力，但插件目录、权限、自动加载和 API 稳定性都未定义；入口见 插件脚本状态.html。
  • 跨服务器全局聊天：当前没有中心服务、账号身份、独立协议和滥用控制基础，不能从好友提醒或服务器内 global 聊天直接扩展；入口见 全局聊天边界.html。
  • BC 未落地功能移植：Media Background 需要按 边界复核 区分底层视频背景和产品化管理；Finish Prediction 已拆为 边界调研，默认不直接实现自动终点 ETA；Split Timer 已拆为 分段计时检查点.html。
  • 配置包导入/导出：.qmconfig 有价值，但需要选择范围、manifest、冲突合并和版本迁移策略；当前先按 QmConfig最小配置包.html 做文件级最小包，不做智能合并。

⑥ 下一批规格队列

这张表不是开发承诺，而是“下一份小规格应该怎么写”。每个条目都必须从当前状态页和源码证据出发，避免把新版 TODO 的整段想法一次性落地。

推荐顺序规格标题最小闭环不要顺手做验收证据
P1QmUi 组件 / 动画 / Theme 收口把现有 QmUi runtime、tokens、theme 和局部动画 helper 的使用规则先收口，避免把“统一”做成全局重构。不做全菜单迁移、不扫全仓库替换局部 helper、不把 theme 扩成完整设计系统。QmUi整合边界.html + 目标组件族源码盘点 + 局部替换验证。
P0F1 聊天导出结构化格式在现有 TXT/HTML/PNG 选择导出基础上，只新增 JSON 或 TOML 一种结构化格式，并固定字段 schema。不扩成完整控制台导出、不做举报平台、不导出远程 rcon。聊天F1结构化导出.html + 新格式样例 + 大 backlog 不长时间无响应的验证。
P0聊天输入与消息行反馈只补输入框焦点态、翻译按钮状态可见性和消息行 hover/按下反馈。不做历史搜索、表情面板、逐条翻译按钮、不迁移消息区到 QmUi 动画运行时。聊天输入反馈.html + 输入/复制/右键菜单回归检查 + 窄屏截图。
P0资源页 Workshop 状态收口把已下载/未下载、作者、下载失败、删除确认和 entity background 层级状态写成稳定 UI/文案规格。不做上传市场、不做资源账号、不做远端审核。资源工坊状态.html + 资源 tab 截图/状态矩阵 + 链接检查。
P1截图水印与地图名命名基于已有 screenshot 和 Screenshots 模式，只增加本地水印/时间戳/地图名命名策略。不做自动上传、不做社交分享、不改截图文件格式。截图水印命名.html + 本地文件命名样例 + 开关配置说明。
P1Skin Frankenstein 可编辑配方在已有部件拖拽、染色、预览和导出能力上，定义可再次打开编辑的 recipe 数据边界。不做 Workshop 上传、不做跨客户端分享码、不做运行时皮肤协议。皮肤拼装配方.html + recipe schema + 导入/导出 round-trip 验证。
P1本地跨局战绩历史最小版只记录本地玩家每局摘要，和 statboard CSV、PlayerStats HUD、中心服 playtime 分层。不做账号系统、不做云同步、不做 Kog 组队榜。本地比赛历史.html + 存储增长限制 + 隐私说明。
P2Bind 指令系统化先补 Chat Binds 自定义列表/删除/编辑边界，再把 BindWheel 扩展为少量客户端开关预设。不重写 DDNet bind、不引入宏/TAS、不做插件平台、不把 Chat Binds 和 BindWheel 合并成一个数据结构。绑定系统化边界.html + BindWheel快速设置.html + 配置域回归检查。
P2Demo/观战导演目标推荐利用现有 Demo marker/slice/speed、Ghost、LiveDirector/MultiView 现状，先定义非画中画的导演目标推荐。不做画中画 UI、不改 demo 格式、不做全自动高光评分。Demo导演目标推荐.html + 目标选择规则 + 性能边界。
P2Split Timer 检查点分段计时基于当前 race time 和检查点事件记录本地分段，只显示当前 run 和 session best 对比。不做 Finish Prediction、不写 demo 格式、不做跨局排行榜或云同步。分段计时检查点.html + race time 重置规则 + checkpoint/手动 split 降级验证。

服务器收藏增强现状

本页接管旧 server-favorites-plan.md。旧方案的“备注、标签、人数通知”方向仍可作为候选，但当前服务器收藏不是单地址 JSON 模型，而是 DDNet 原生多地址 favorite group、allow_ping 和 favorite community 组合。

当前事实

领域状态当前实现影响
服务器地址收藏implementedIFavorites::CEntry 保存最多 MAX_SERVER_ADDRESSES 个地址和 m_AllowPing。一个收藏可以是地址组，不应按单地址结构体直接重写。
持久化格式config commands保存为 add_favorite、begin_favorite_group、end_favorite_group，allow_ping 作为可选参数。新增元数据时要兼容 DDNet 配置导入/导出，不宜替换原格式。
浏览器 UIimplemented服务器详情面板已有 Favorite 三态勾选和 Leak IP / allow ping 切换。备注/标签 UI 应靠近详情面板或右键菜单，不要抢占现有收藏语义。
收藏社区implementedFavoriteCommunitiesFilter 保存最多 5 个 favorite community，并按用户顺序生成浏览器页面。旧“标签分组”不能忽略已有 community 页面；标签应只做用户私有补充。
地图收藏separate地图收藏、地图备注和 Favorite Maps 页已经在 收藏浏览状态.html 里维护。不要把地图收藏 JSON 方案直接套到服务器收藏核心。
人数变化通知missing本轮未看到专门监控收藏服务器人数变化的实现。需要先定义刷新频率、只监控 allow ping 或当前列表内服务器、通知去重和隐私边界。

旧计划修正

旧判断/方案当前修正
IFavorites 只有 Add(const NETADDR &Addr) / Remove / AllFavorites。已过时。当前接口接收地址数组，返回 TRISTATE，支持 AllowPing 和 AllEntries。
直接新增 SFavoriteInfo 到 favorites.h，把 note/tag/add time 放进核心收藏。风险偏高。核心收藏是 DDNet 兼容模型，建议优先做 QmClient sidecar 元数据，用地址组 key 关联 note/tag。
保存到 qmclient_favorites.json 替代原收藏。不应替代原收藏。可以新增 sidecar，但 add_favorite、favorite group 和 allow_ping 必须继续可用。
新增 cl_favorite_monitor* 配置。命名不适合 QmClient 新配置；若新增应使用 qm_ / Qm，并先明确是否属于浏览器、通知或 QmClient 设置域。
人数变化通知直接定时遍历所有收藏服务器。需要降级。服务器浏览器刷新有网络、隐私和误报成本，默认不应后台高频 ping 未允许 ping 的收藏。

建议下一版最小计划

优先级主题范围验收点
P0服务器收藏现状固定用户文档明确 Favorite、Leak IP、favorite group、favorite community 的区别。旧“单地址收藏接口”不再作为实现依据。
P1sidecar 备注最小版新增 QmClient 私有元数据文件，按规范化地址组 key 保存 note；不改 IFavorites 存储语义。删除收藏时能清理或保留孤儿 note 有明确策略；旧收藏仍可加载。
P2标签/分组在 sidecar 上做用户标签，不取代 favorite community 页面。标签筛选只影响 UI 视图，不改变 DDNet 原生 favorite community。
P3人数变化通知只监控允许 ping 或浏览器当前已知的收藏服务器，并使用现有 Qm 通知/HUD 通知边界。有冷却、去重、禁用开关和刷新成本说明。

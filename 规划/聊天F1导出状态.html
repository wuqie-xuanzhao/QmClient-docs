能力当前实现说明

旧计划修正

旧结论当前修正
聊天记录仅存在内存中，无法导出。不再准确。F1 本地控制台可以选择玩家聊天并导出 TXT/HTML/PNG。
第一阶段要添加 export_chat 命令并支持 TXT/JSON。当前入口是 UI 选择导出，不是控制台命令；JSON 尚未看到实现，TXT/HTML/PNG 已存在。
配置变量建议使用 cl_chat_export_*。不应继续使用 cl_ 作为 QmClient 新配置前缀；若后续加配置，应走 qm_ / Qm 前缀并放入 QmClient 配置域。
只考虑聊天组件的 m_aLines[MAX_LINES]。新版 TODO 关注 F1 控制台内容；当前导出实现基于 console backlog，而不是只导出聊天组件 64 行环形数组。

仍未完成的规划点

  • 新版 TODO 点名 JSON / TOML 结构化导出；当前复核只看到 TXT / HTML / PNG，JSON / TOML 仍应保留为规划项。
  • 导出目标目前是本地控制台玩家聊天；完整 F1 内容、系统信息、echo 信息的可选导出还需要重新定义范围。
  • 当前 PNG 导出在主线程构建图片并保存，多消息大导出是否卡顿需要实测或添加预算/分帧设计。
  • 导出 UI 仍是 F1 顶栏按钮，不是独立美化面板；筛选、多次筛选后导出、折叠重复系统消息还需要新规格。
  • 如果要作为举报证据，需要补服务器信息、时间戳、客户端版本、文件完整性元数据等可信上下文。

建议下一版最小计划

阶段范围验收点
P0 状态固定把当前 TXT/HTML/PNG 导出能力补成正式现状文档和 UI 文案检查。能明确从 F1 本地控制台选择玩家聊天并导出，输出路径和格式可被用户找到。
P1 结构化导出新增 JSON 或 TOML 之一，不同时扩展全部格式。结构中包含时间、原始行、显示文本、本地玩家判断、导出版本；小规格见 聊天F1结构化导出.html。
P2 卡顿控制大批量 PNG/HTML 导出加性能观测，必要时拆分任务或延迟写入。导出大量消息时不造成明显长帧或无响应。
P3 F1 完整导出再讨论是否导出系统、echo、console 命令和远程控制台。有明确筛选模型，避免把敏感命令或无关日志误导出。

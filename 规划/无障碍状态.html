无障碍与可读性现状

本页接管旧 accessibility-plan.md。旧报告把当前状态写成“几乎为零”过于绝对；更准确的结论是：专门色盲/高对比/通用键盘焦点体系仍缺失，但已有分散的字体、缩放、透明度、颜色和 Focus Mode 能力。

当前结论

主题状态当前事实口径修正
专门色盲模式missing未看到 colorblind 或 qm_colorblind_mode 一类配置。旧方案方向有效，但不能假设已有统一颜色管线。
高对比模式missing未看到 high_contrast 或全局高对比开关。可以复用现有 UI opacity/color 管线做局部入口，不应先重写整套 UI。
全局 UI 缩放not verified当前只确认到多个局部缩放配置，未确认可直接接入的全局 qm_ui_scale。旧文档“在 adapter 加全局缩放因子即可”的判断需要降级。
局部可读性控制exists已有自定义字体、光标缩放、pie menu 缩放、input overlay 缩放、聊天气泡字体、UI/HUD 透明度等配置。无障碍规划应先盘点并串起这些入口，避免重复造设置项。
键盘操作partial已有 Enter/Escape/Tab 等局部 hotkey，但未看到通用 Tab 焦点导航或 focus ring。键盘焦点导航属于 UI 系统级工作，不适合塞进一个小视觉增强补丁。
Focus ModerelatedQmFocusMode 会隐藏 HUD、名字板、方向提示、聊天、特效和部分声音。它能降低干扰，但不是完整无障碍模式；文档中应单独标为相关能力。

颜色依赖风险

红/绿和纯颜色语义仍是主要缺口。先修一个高频路径，比一次性抽象全局 GetAccessibleColor 更容易验证。

位置当前能力缺口建议处理
服务器浏览器 ping使用 green-red HSL 映射。未确认有类似 cl_enable_ping_color 的浏览器侧关闭或替代入口。优先加非红绿 palette 或文字/符号辅助。
计分板 pingcl_enable_ping_color 可关闭 ping 着色。关闭后只是减少颜色依赖，不提供更好的色盲友好映射。可作为第一批可控路径之一。
名字板 ping 圆环tc_nameplate_ping_circle 可关闭。仍依赖延迟颜色语义。新增模式前先确认圆环是否应跟随同一 ping palette。
队伍、状态、时间差多处红/蓝、红/绿硬编码。不同上下文语义不同，不能简单套同一渐变。后续按上下文拆：team、status、delta、identity。

旧计划修正

旧判断当前修正
“当前项目几乎没有无障碍相关实现”。专门无障碍模式基本缺失，但已有分散的可读性和低干扰控制。
新增配置写入 config_variables_qimeng.h。该路径已过时；当前 QmClient 配置主文件是 config_variables_qmclient.h，新配置应使用 qm_ / Qm。
直接新增全局 qm_ui_scale 并在 adapter 层统一缩放。全局 UI 缩放影响范围大，必须先复核 UI 布局、文本裁切、鼠标命中和旧 DDNet UI 兼容。
一次性替换所有硬编码颜色。建议先选 ping 或一条状态路径做可验证改造，再扩大到 team/status/delta/identity。

建议下一版最小计划

优先级主题范围验收点
P0可读性设置盘点把现有字体、缩放、透明度、Focus Mode、ping color 开关整理到用户可找到的位置。不新增功能也能让用户知道哪些现有设置可用。
P1ping 颜色替代方案优先选浏览器 ping 或计分板 ping 一条路径，提供非红绿 palette 或非颜色辅助标识。色盲友好模式可开关，默认不改变现有视觉。
P2高对比小入口基于现有 UI opacity/color 或单个 HUD 区块增强边框/背景对比。不引入大范围主题系统，不破坏现有皮肤/主题。
P3通用焦点导航单独立项，先设计 UI focus model。Tab 顺序、focus ring、鼠标/键盘状态一致性都有规格和测试点。

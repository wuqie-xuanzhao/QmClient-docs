聊天框 UI 增强现状

本页接管旧 chat-ui-enhancement-plan.md。当前聊天框不是“缺少交互基础设施”的状态：翻译按钮、滚轮历史、点击复制、右键行菜单和草稿保留已经存在；剩余重点是输入框视觉、消息行 hover/动效和是否值得把消息区迁移到 QmUi 动画运行时。

当前已存在的能力

能力状态当前实现口径
聊天消息渲染implementedchat.cpp 仍直接计算布局、背景、Tee 头像和文本容器；可见区溢出用 m_CutOffProgress 做淡出和水平偏移。

旧计划修正

旧判断当前修正
聊天框缺少鼠标交互、复制和逐条操作。已过时。当前已有复制、右键菜单、回复、复读、屏蔽和静音等行级操作；后续只能说“hover 反馈和更细粒度操作仍可增强”。
聊天框翻译按钮仍是待设计功能。已过时。输入框侧翻译按钮和自动出站翻译已经存在；历史消息行尾独立翻译按钮未作为当前事实写入。
消息区动画应高优先级迁移到 QmUi。需要降级。头顶气泡已经使用 QmUi 动画，但消息区迁移会触碰聊天核心渲染、复制命中、backlog 可见性和性能，应作为重构专项，而不是普通视觉增强的第一步。
配置文件是 config_variables_qimeng.h。已过时。当前 QmClient 配置在 src/engine/shared/config_variables_qmclient.h，上游聊天配置仍在 config_variables.h。
qm_chat_fade_out_anim 是当前配置。本次源码复核未在当前配置头里找到该变量；旧文档不应继续把它列为已存在配置。

建议后的最小规划

阶段范围验收点
P0 文档收口把旧 Markdown 标为被本页接管，后续入口只读 HTML。开发前能快速看出哪些“缺失”已被当前代码实现。
P1 输入框视觉只增强输入框背景、焦点态、翻译按钮间距和命令预览层级。不改变发送、补全、输入法、翻译菜单和鼠标选择行为。
P2 消息行反馈增加 hover 高亮、命中区域可视反馈、右键菜单入口提示。复制/右键菜单命中与现有行为一致，旧版 cl_chat_old 不被破坏。
P3 动效统一调研单独评估消息区是否迁移到 CUiV2AnimationRuntime。有性能预算、缓存失效策略和回退开关，再决定是否实现。

不要把 P1/P2 和 QmUi 迁移绑在一起做。聊天组件承担输入、历史、翻译、复制、右键菜单、控制台命令和 HUD editor 预览等职责，动效重构的回归面明显大于普通样式调整。

仍是缺口

  • 输入框没有明确的现代化背景、边框焦点态和字符计数器。
  • 消息行 hover 状态和点击命中反馈仍偏弱。
  • 聊天消息区没有使用 QmUi 动画运行时；目前只有头顶聊天气泡接入。
  • 历史搜索、表情面板、逐条翻译按钮、消息操作工具条都不是当前已证实能力。
  • qm_chat_anim_style、qm_chat_input_bg、qm_chat_cursor_blink、qm_chat_msg_gap 仍只是旧方案建议，本次未看到当前配置实现。

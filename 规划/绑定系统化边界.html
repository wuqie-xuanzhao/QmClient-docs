Bind 指令系统化边界规格

本文把旧 “Bind 指令系统化” 拆成可执行边界：DDNet 原生 bind 保持不重写，BindWheel 快捷设置已有独立小规格，本页只定义 BindChat 管理 UI、Tab 补全接入和配置包边界。目标是让绑定能力更可发现，而不是把它扩成宏、脚本或自动化平台。

当前结论 三层边界 本规格范围 建议阶段 验收边界 复核证据

当前结论

主题状态后续口径
DDNet 原生 bind基础能力已存在不重写 CBinds，不改原生 bind/unbind 语义。
BindWheel 快捷设置已有独立规格继续看 BindWheel快速设置.html，不和 Chat Binds UI 合并实现。
Chat Binds 管理 UI缺口明确当前设置页主要管理默认绑定名；后续可补自定义绑定列表、命令编辑、删除和搜索。
Chat Binds Tab 补全函数存在 / 未接入可作为独立小任务接入聊天 Tab 补全，但必须不破坏玩家名、服务器命令和 slash command 补全。
配置导入/导出归入配置包Chat Binds 和 BindWheel 的统一备份/迁移应走 .qmconfig 最小包规格。

三层边界

层级数据/配置域允许改进禁止顺手做
原生键盘 bindCBinds 与 DDNet 原生 bind 配置只补文档和 UI 引导。不重写输入系统、不改按住式命令释放语义。
Chat BindsConfigDomain::TCLIENTCHATBINDS，QmClient/qmclient_chatbinds.cfg管理 UI、搜索、删除、自定义项编辑、Tab 补全。不把普通聊天自动化，不推荐刷屏或服务端命令。
Bind WheelConfigDomain::QMCLIENT，普通 add_bindwheel 行安全客户端设置白名单预设。不做条件宏、多级轮盘、脚本平台或 TAS。

本规格范围

允许进入 P0/P1

  • 在 Chat Binds 设置页显示当前自定义绑定列表。
  • 允许编辑自定义绑定的触发名和命令。
  • 允许删除自定义绑定，并清楚地区分默认绑定和用户自定义绑定。
  • 为新增自定义绑定提供 ! 前缀建议或警告，降低普通聊天误触发。
  • 把 ChatDoAutocomplete() 接入聊天框 Tab 补全，但只在当前 token 像 chat bind 触发名时参与。

不进入本规格

  • 把 m_vBinds 立刻替换成 map 或重写保存排序。
  • 把 Chat Binds 和 BindWheel 合并成一个统一数据结构。
  • 新增宏语法、条件、延迟、循环、脚本执行或自动玩法。
  • 改 DDNet 原生 bind 的配置格式。
  • 在没有配置包计划的情况下做导入/导出 UI。

建议阶段

阶段最小闭环验证重点
P0 Chat Binds 列表设置页显示自定义绑定列表，支持删除和只读命令展示。默认绑定重命名仍可用；保存文件仍写 bindchat/unbindchat。
P1 自定义绑定编辑增加 name/command 编辑和新增按钮，复用现有 AddBind() / RemoveBind()。重复名称、空名称、超长命令、默认绑定覆盖行为清楚。
P1 Tab 补全接入在聊天 Tab 补全中加入 Chat Binds 候选。玩家名补全、服务器命令补全、slash command 不回归。
P2 配置包联动把 Chat Binds / BindWheel 纳入 .qmconfig 文件级导出说明。和 QmConfig最小配置包.html 保持一致，不另建格式。

验收边界

  • Chat Binds 管理 UI 改动不得影响原生 bind、+bindwheel 和 BindWheel 设置页。
  • 新增/删除/编辑 Chat Binds 后，保存文件仍是 QmClient/qmclient_chatbinds.cfg 中的 console command 行。
  • 默认绑定未改时不应写出重复 bindchat；删除默认项仍应写 unbindchat。
  • Tab 补全必须保留 Shift 反向循环、玩家名补全和命令补全体验。
  • UI 文案要明确 Chat Binds 会拦截聊天输入，普通词绑定有误触发风险。

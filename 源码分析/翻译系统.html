结论摘要

聊天翻译由 `CTranslate` 组件承载，支持手动翻译最近聊天、按玩家 id 翻译、入站自动翻译和出站发送前翻译。后端通过配置选择 LibreTranslate、FTAPI、Tencent Cloud 或 LLM API；每个 job 通过 HTTP backend 更新结果，并把结果挂回聊天行或发送队列。

本页只描述聊天内容翻译。源码字符串提取、TOML 维护库和运行时语言包生成属于 多语言系统。

运行/调用流程

1. 后端选择`CreateTranslateBackend()` 根据 `g_Config.m_QmTranslateBackend` 创建 LibreTranslate、FTAPI、Tencent Cloud 或 LLM backend。
2. 手动翻译`translate` 和 `translate_id` 控制台命令调用 `Translate()`，从聊天环形缓冲里选最近的可翻译玩家消息。
3. 入站任务`Translate(CChat::CLine &)` 检查并发、排除服务器消息，创建 `CTranslateJob`，并把 response 指针挂到聊天行。
4. 出站任务`TryTranslateOutgoingChat()` 解析目标语言，创建 `COutgoingTranslateJob`，完成后通过 `SendChatQueued()` 发送译文。
5. 渲染轮询`OnRender()` 轮询 HTTP backend；成功时更新聊天行并 `RebuildChat()`，失败时写入错误文本。
6. 自动翻译`AutoTranslate()` 根据开关、本地玩家、服务器消息、FTAPI 保护、数字/目标语言启发式过滤后启动入站翻译。

边界与风险

  • 可依赖事实：聊天翻译是 HTTP job 驱动的运行时功能，不会写回 `translations/i18n/*.toml`。
  • 并发边界：`GetEffectiveConcurrency()` 按后端设置默认并发；FTAPI 默认最低，LLM/TencentCloud 较高。
  • 隐私边界：聊天文本和密钥会进入外部服务请求；文档和设置页应明确区分本地语言包与远端翻译。
  • 显示风险：聊天行重用通过 line index 和 translation id 防护；改聊天缓冲结构时要同步检查翻译响应生命周期。

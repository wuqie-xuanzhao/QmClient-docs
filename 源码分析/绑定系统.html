结论摘要

基础键位绑定由 DDNet 的 `CBinds` 承载，`bind`、`binds`、`unbind`、`unbindall` 仍是权威配置入口。QmClient 在输入栈上额外接入 `CKeyBinder`、`CBindChat` 和 `CBindWheel`：设置页用 `CKeyBinder` 捕获新键位，聊天绑定和轮盘绑定则是 TClient 功能层，最终仍通过控制台命令执行。

绑定系统不是单一页面功能。修改键位行为时要同时检查输入栈顺序、设置页读取器、控制台保存回调和 TClient 扩展绑定。

运行/调用流程

1. 组件注册`CGameClient::OnConsoleInit()` 把 `m_Binds`、`m_BindChat`、`m_BindWheel`、`m_KeyBinder` 放入组件列表，并在输入栈里让 `m_KeyBinder` 优先接管按键捕获。
2. 配置命令`CBinds::OnConsoleInit()` 注册 `bind`、`binds`、`unbind`、`unbindall`，`ConBind()` 解析键名后调用 `CBinds::Bind()`。
3. 存储绑定`CBinds::Bind()` 按修饰键组合和 key id 写入 `m_aapKeyBindings`，并刷新 `g_Config.m_QmDeepflyMode`。
4. 输入执行`CBinds::OnInput()` 在 press/release 时查找当前修饰键绑定，执行 stroked console command，并跟踪 active binds。
5. 设置页编辑`CMenusSettingsControls::Render()` 调用 `CKeyBinder::DoKeyReader()` 捕获或清空键位，再把变化写回绑定项。
6. 扩展绑定`CBindWheel` 注册 `+bindwheel` 和管理命令，轮盘关闭时执行选中命令；`CBindChat` 负责聊天命令别名。

边界与风险

  • 可依赖事实：基础按键绑定仍以 `CBinds` 为中心，设置页和扩展功能都围绕控制台命令工作。
  • 输入优先级：`m_KeyBinder` 在输入栈最前，设置页捕获键位时会阻断后续组件；轮盘、聊天、菜单、控制台也会影响 release 处理。
  • 配置风险：绑定字符串可以包含嵌套 bind/unbind/exec；修改解析规则会影响配置兼容性。
  • QmClient 特有耦合：`CBinds::Bind()` 会刷新 deepfly 模式，不能把它当成纯 DDNet 绑定存储。

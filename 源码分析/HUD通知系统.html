HUD 通知系统源码分析

本页分析 QmClient 的 HUD 通知链路：聊天 Echo、服务器系统消息分类、隐藏/路由决策、通知队列、HUD 渲染、编辑器测量和 QmClient 设置页配置。

结论摘要

HUD 通知系统由 `CQmHudNotifications` 组件承载。聊天组件负责把 Echo 和服务器聊天消息交给通知组件；通知组件使用 `hud_notification_rules.cpp` 对服务器消息做语义分类，再根据配置决定隐藏、保留聊天行或入队通知。渲染侧按最大可见数、停留时间、动画、颜色和锚点计算可见通知。

这套系统既影响 HUD，也影响聊天行是否显示。改规则时不能只看渲染函数，还要检查 `CChat::OnMessage()` 和 `CChat::ResolveLineServerMessageClass()`。

运行/调用流程

1. 组件注册`CGameClient::OnConsoleInit()` 的组件列表包含 `m_QmHudNotifications`，因此它参与 reset/render/message 生命周期。
2. Echo 路由`CChat` 在 Echo 输出路径调用 `m_QmHudNotifications.QueueEcho()`，通知组件会固化 Echo 文本和颜色。
3. 服务器消息`CChat::OnMessage()` 对服务器聊天调用 `HandleServerChat()`，通知组件返回是否消费/隐藏，并回填 `SServerMessageAnalysis`。
4. 规则决策`AnalyzeServerMessage()` 识别 solo、help/basic info、team、swap/rescue、vote、status 等语义；`DecideServerMessageEntry()` 根据配置决定是否入队或隐藏。
5. HUD 渲染`CQmHudNotifications::OnRender()` 计算 HUD 锚点、可见区域、动画和颜色，并调用 `RenderNotifications()`。

分类与配置

类别来源影响
PromptSolo、team、swap/rescue、vote moderation、status 等规则。可显示为系统通知，也可被 focus/隐藏配置消费。
BasicInfo基础服务器信息或明确排除的系统提示。影响聊天 focus 过滤和是否入队。
HelpInfo帮助、用法、示例类服务器消息。可被高级分类过滤控制。
Unknown无法识别但可按系统消息处理的文本。受 “Show unknown server messages” 控制。
Echo聊天组件 Echo 输出。可继承聊天颜色或使用通知覆盖色。

边界与风险

  • 可依赖事实：通知系统已接入组件生命周期，服务器消息分类和 Echo 入队都有代码路径。
  • 关键耦合：聊天行 `m_ServerMessageClass` 用于 focus 过滤；通知规则变化会影响聊天显示，不只是 HUD。
  • 配置边界：基础开关、高级分类过滤、颜色、动画、最大可见数和边距都在 QmClient 设置页配置。
  • 维护风险：新增服务器消息规则时要同步考虑本地化文本、fallback、隐藏逻辑和测试覆盖，避免把普通信息误路由为强提示。

结论摘要

资源页主逻辑集中在 `menus_settings_assets.cpp`。资源列表由后台 `CAssetListLoadJob` 扫描本地目录/地图文件生成，卡片预览由 `settings_resource_preview.*` 管理状态、artifact job 和 GPU 上传队列；通用预算函数在 `settings_resource_jobs.*` 中限制滚动、跳转和上传压力。

资源页不是简单图片列表。当前实现把扫描、预览生成、上传和 UI 卡片分层处理，主要目标是避免切换标签或滚动时一次性加载过多资源造成卡顿。

运行/调用流程

1. 扫描列表`CAssetListLoadJob` 按资源类别扫描 `assets/...` 或 map 文件目录，生成 `SSettingsAssetMergeEntry` 列表。
2. 卡片壳层资源页先渲染稳定卡片和元数据缓存，滚动/切换标签时可进入 shell-only 或低预算路径。
3. 预览任务`CSettingsResourcePreviewJob` 在后台构建预览 artifact，必要时缩放图片，避免直接在 UI 帧做重活。
4. 上传预算`CSettingsResourcePreviewUploadScheduler::Drain()` 按上传预算把 artifact 变成 GPU texture，预算不足则留在队列。
5. 工具栏操作资源页工具栏提供资源目录、资源编辑器、workshop 显示/同步、实体预览切换和刷新。
6. 缓存失效刷新按钮会清空当前 tab 的自定义项、重置 workshop 状态，并触发设置运行时缓存失效。

边界与风险

  • 可依赖事实：本地资源扫描、预览 artifact 和 GPU 上传已经分离，资源页可在预算内逐步补齐预览。
  • 性能边界：滚动、跳转滚动和 post-scroll recovery 会改变重任务/上传预算；不能把资源页改成同步全量加载。
  • 路径边界：不同资源类型有不同安装目录和文件规则，entity background 还会递归扫描 map/背景文件。
  • 维护风险：新增资源类别要同步 registry、扫描规则、预览路径、工具栏能力和缓存失效路径。

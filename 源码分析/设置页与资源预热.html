设置页与资源预热源码分析

本页分析设置页打开和切换时的渲染、文本预构建、资源列表、预览缓存与 GPU 上传预算。这里的重点不是单个设置项，而是防止设置页卡顿的运行路径。

结论摘要

设置页性能链路分成两段：启动加载期通过 `PrewarmSettingsRuntimeCachesDuringLoading()` 预热设置页和文本容器；运行期由 `OnUpdate()` 根据当前设置页决定资源和 GPU 上传预算。QmClient 设置页本身通过 `RenderSettingsQmClient()` 承载模块卡片、搜索、折叠、拖拽、滚动裁剪和 perf 日志。

这不是“资源页单独优化”的问题。皮肤、资源、QmClient 设置页、文本容器和 GPU 上传共享同一套 frame budget 思路，文档和后续修复应该按这条链路理解。

运行/调用流程

1. 启动加载`CGameClient::OnInit()` 在资源加载阶段调用 `PrewarmSettingsRuntimeCachesDuringLoading()`，先触发 `m_Menus.PrewarmSettingsPages()`。
2. 文本预构建预热循环中调用 `PrewarmSettingsTextPoolForLoading()`，并用 `SettingsTextContainerCount()`、`SettingsTextPrebuildRemaining()` 记录进度。
3. 运行期预算`CGameClient::OnUpdate()` 判断 Tee/Assets 设置页是否激活，再调用 `SettingsGpuUploadLimitForFrame()` 和 `ResetSettingsFrameBudgetForFrame()`。
4. 设置页分发`CMenus::RenderSettings()` 在 QmClient 设置页分支调用 `RenderSettingsQmClient(ContentView, false, CollectingMenuTextPlan)`。
5. QmClient 页面`RenderSettingsQmClient()` 处理 tab、滚动区域、模块卡片、搜索/折叠/拖拽，并在 perf debug 时写 `perf/qmclient`。

资源预算模型

函数职责边界
SettingsResourceFrameStageBudget按 frame context、优先级和滚动可见状态选择阶段预算。用于避免一次性处理太多可见/后台资源。
SettingsResourceSharedHeavyBudget给共享 heavy work 设置常规和恢复预算。恢复模式和普通帧的预算不同。
SettingsResourceUploadWithinByteBudget按上传次数和字节预算判断是否允许继续上传。控制 GPU 上传峰值。
SettingsResourceOversizedUploadAllowed对超预算单项上传做例外判断。页面切换、优先级和 oversized 次数都会影响结果。
SettingsResourceCanUseHighPriorityBudget判断高优先级资源是否能使用额外预算。不能把高优先级当作无限加速。

边界与风险

  • 可依赖事实：设置页启动期预热和运行期预算已经存在，且由 `CGameClient` 统一驱动。
  • 阶段性状态：QmClient 设置页仍是大型函数和局部 lambda 组合，模块化更多体现在卡片注册/搜索/渲染分支，而不是独立组件树。
  • 性能风险：新增资源预览、文本容器或 GPU 上传路径时，必须接入现有预算接口，不能绕过 frame budget。
  • 文档风险：旧 `docs/superpowers` 中的页面卡顿/设置页计划可能仍有价值，但实现依据必须回到本页列出的当前源码。

客户端 UI 架构源码分析

本页分析当前客户端 UI 的分层关系：DDNet 旧 `CMenus` / `CUIRect` 仍是大量页面的承载层，QmUi 提供 runtime、动画、布局、token 和 widget 原语，并通过 QmClient 设置页 dogfood 渐进接入。

结论摘要

当前 UI 架构不是完全重写后的声明式 UI。`CGameClient` 持有 `CUiRuntimeV2` 并在每帧推进 runtime；`CMenus` 和大量页面仍用 `CUIRect`、`DoButton_Menu`、局部绘制函数组织界面。QmUi 的价值在于提供可复用 runtime、动画、布局、token/theme 和 widget 原语，让新页面能逐步脱离散落的局部样式。

不要把 `src/game/client/QmUi/` 的存在解读为“主菜单、HUD、计分板都已迁移完成”。当前事实是渐进接入，尤其 QmClient 设置页仍大量混用传统菜单绘制和 QmUi dogfood。

架构层次

层次代表路径当前职责
客户端帧入口src/game/client/gameclient.cpp初始化 UI、推进 `CUiRuntimeV2`、渲染组件和菜单。
旧菜单承载层src/game/client/components/menus*.cppDDNet/TaterClient 传统菜单体系，仍使用 `CMenus`、`CUIRect`、按钮容器和滚动区域。
QmClient 设置页src/game/client/components/qmclient/menus_qmclient.cppQmClient 功能设置入口，也是 QmUi dogfood 的接入点。
QmUi runtimesrc/game/client/QmUi/QmRt.*聚合 tree、animation runtime、layout engine、render bridge 和 perf stats。
QmUi 组件原语src/game/client/QmUi/Ui*.h/.cpp按钮、表单、导航、容器、overlay、context 和 dogfood 页面。

运行/调用流程

1. 初始化`CGameClient::OnInit()` 初始化旧 `m_UI`，随后调用 `m_UiRuntimeV2.Init(this)`，QmUi runtime 获得 `CGameClient` 上下文。
2. 重置`CGameClient::OnReset()` 调用 `m_UiRuntimeV2.Reset()`，runtime 清空 tree、animation runtime、render bridge 统计和 perf context。
3. 每帧推进`CGameClient::OnRender()` 在组件渲染前设置 QmUi perf context，并调用 `m_UiRuntimeV2.OnRender()`。
4. Runtime 内部`CUiRuntimeV2::OnRender()` 依次执行 tree begin、动画推进、render bridge begin、tree end，并写入节点数、动画数和耗时。
5. 页面接入`RenderSettingsQmClient()` 在 `dbg_qm_ui_dogfood` 开启时组装 `IUiContext`，把 `Ui()`、`Tooltips()`、`QmIconManager()` 和 `AnimRuntime()` 传给 dogfood 页面。

QmUi 组件边界

模块当前能力边界
QmLayout.*提供 row/column、flex、percent、padding、gap、align、justify 和 min/max 约束。输出仍可回到 `CUIRect` 世界。
QmAnim.*提供属性动画、tween/spring、delay、interrupt policy、完成事件和 motion level。需要页面用稳定 node key 接入。
QmRender.*记录 draw call 和 clip push 统计。不是独立 renderer，不替代 `IGraphics`。
UiButtons.*封装 primary、secondary、icon button，并复用 `CMenus::DoButton_Menu`。仍依赖 `CMenus` 和旧按钮行为。
UiForms.*提供 text field、toggle、slider。输入与绘制仍走旧 `CUi` / `CLineInput` 能力。
UiNavigation.*提供 tab bar 和 list item。tab 仍调用 `DoButton_MenuTab`。
UiDogfood.*集中展示 widget hover/focus/disabled/selected/缩放状态。是验证入口，不是正式设置页重写。

边界与风险

  • 可依赖事实：`CUiRuntimeV2` 已由 `CGameClient` 初始化、重置并每帧推进；动画 runtime 可以通过 `GameClient()->UiRuntimeV2()->AnimRuntime()` 传入页面。
  • 阶段性状态：QmClient 设置页有 dogfood 入口，但大量设置卡片仍是 `CUIRect` 手写布局和 `CMenus` 控件。
  • 不可推导：不能从 QmUi token/theme 推导出全局视觉系统已经统一；旧菜单颜色、局部样式和配置变量仍并存。
  • 维护风险：新 widget 若直接包裹旧 `DoButton_Menu`，需要继续遵守旧 UI 的 hot item、按钮 id、tooltip 和裁剪规则。

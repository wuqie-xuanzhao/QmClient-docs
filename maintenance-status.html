QmClient 文档维护状态

本页固定 docs/dyl/QmClient_docs 的维护边界：HTML 状态页是当前入口，归档 Markdown 是来源材料，新版 TODO PDF 是规划参考而不是源码证据。

① 权威入口 ② 归档口径 ③ TODO PDF 口径 ④ 后续维护流程

① 权威入口

日常阅读从 index.html 开始。当前事实看 current/，规划看 planning/，调研看 research/，旧材料看 archive/。

区域当前状态维护规则
current/HTML-first只放当前代码现状页。改动事实前必须复核源码、脚本或 gate 入口。
planning/规划路由只说明后续可以做什么。进入开发前必须重新写小规格/计划。
research/调研状态记录已复核的调研结论和风险，不替代源码阅读。
archive/历史材料已知过时或被 HTML 接管，不可直接作为实现依据。

② 归档口径

  • archive/superseded-current/ 保存从当前说明迁出的 Markdown，当前事实以同名或对应 HTML 为准。
  • archive/superseded-planning/ 保存旧方案稿，只能用来追溯想法来源。
  • archive/superseded-research/ 保存旧调研原文，引用前必须先读对应 HTML 状态页。
  • 继续出现 config_variables_qimeng.h、QIMENG、RiVoice、qmc_、cl_plugins_*、cl_stats_* 等旧口径时，默认先按当前 HTML 状态页重写。

③ TODO PDF 口径

新版 TODO PDF 位于 E:/下载文件/QmClient 功能 Todo.pdf，本轮已能通过本地 PDF 提取工具读取，共 11 页。它提供优先级和想法来源，但其中“已完成”状态不等于当前代码已经可维护。

PDF 主题当前承接入口使用方式
新版 TODO 总路由planning/todo-priority-status.html先看它判断旧计划是否降级、重写或继续。
创新功能筛选planning/innovation-roadmap.html把近期可产品化、中期方向和默认不做分开。
页面切换、资源页、翻译、F1 导出、Demo/观战、统计、配置包、自动更新、BC 移植planning/index.html 和对应状态页进入开发前只取一个小闭环，不按 PDF 整页打包实现。

④ 后续维护流程

  • 新增当前事实：先读源码或脚本，再更新 current/*.html 或 research/*.html。
  • 新增规划：先连接到 planning/index.html，并明确它不是实现计划。
  • 发现旧文档错误：把旧 Markdown 留在归档区，并在对应 HTML 中写清替代入口。
  • 新增 HTML：复用 ../../qmclient-html-template.html 的视觉语言，保证相对链接可检查。
  • 完成文档改动后运行 HTML 相对链接检查和 python qmclient_scripts/gate/check_docs.py。

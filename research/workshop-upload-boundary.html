Workshop 上传与资源服务边界调研

本文把“资源页 Workshop 状态收口”和“资源上传/分享市场”拆开。当前 QmClient 资源页已有 catalog 浏览、下载、删除、本地作者缓存和预览调度；未见账号、上传、审核、远端发布或资源市场闭环。

① 快速结论 ② 当前已有链路 ③ 上传市场缺口 ④ 风险边界 ⑤ 可行推进路径 ⑥ 源码证据

① 快速结论

资源页 P0 应继续做“状态收口”：已下载/未下载 tag、作者显示、下载失败、删除确认、entity background 层级。不要把它扩大成上传市场、账号系统或远端审核平台。

问题结论可信度
当前是否能浏览 Workshop 资源？能。当前代码从 assets.json catalog 拉取资源，按 tab/category 过滤并合并本地列表。高
当前是否能下载 Workshop 资源？能。卡片有下载确认，使用 HTTP 下载到当前类别安装路径，并保存本地作者缓存。高
当前是否有上传/发布远端资源？未见。没有客户端上传请求、账号权限、审核状态、远端发布 API 或资源市场模型。中高
PublishSettingsAssetMergeEntries 是否是上传？不是。它是本地资源列表 merge entry 发布/刷新命名，不代表远端 Workshop publish。高

③ 上传市场缺口

  • 账号/身份：当前资源页没有上传身份、作者认证、登录态、token 或账号绑定 UI。
  • 上传协议：当前资源页证据指向 catalog 读取和 HTTP 文件下载；未见资源上传表单、multipart、POST 发布或远端更新 catalog 的客户端链路。
  • 审核与安全：没有内容审核、版权提示、恶意资源扫描、撤回、举报或黑名单流程。
  • 服务端存储：没有资源包 manifest、对象存储、hash 去重、版本迁移、缩略图生成或缓存失效规格。
  • 失败恢复：没有上传断点续传、重试、冲突命名、配额、速率限制和离线队列。

因此，Workshop 上传/分享市场不能从资源页 UI 小改直接进入实现。它需要单独的服务、协议、安全和治理规格。

④ 风险边界

风险为什么重要默认处理
版权/恶意内容上传资源可能包含侵权、恶意图片、畸形 map/entity 文件或误导性缩略图。先调研审核和禁用机制。
账号与隐私作者、上传者、IP、下载记录和举报都可能成为用户数据。没有身份方案前不做上传。
远端依赖catalog 当前是只读 JSON；上传会引入服务可用性、缓存一致性和回滚问题。先定义数据源和发布 API。
性能上传/市场 UI 容易和资源页预览调度、缩略图下载、GPU 上传竞争。继续复用资源页预算，不引入全量同步。

⑤ 可行推进路径

阶段允许做什么不做什么
P0 状态收口按 resources-workshop-status-spec.html 改进已下载/未下载/本地-only/失败状态。不做上传按钮。
P1 数据源调研定义资源 manifest、catalog 字段、作者/版本/缩略图关系和本地缓存策略。不要求客户端立即发布远端资源。
P2 服务端/审核规格讨论账号、权限、审核、撤回、举报、配额、对象存储和 CDN/cache。不把中心服或语音服务临时改成资源市场。
P3 opt-in 上传原型仅在服务端和审核边界明确后，做本地打包、预检、上传草稿和失败恢复。不影响现有只读 catalog 浏览和下载。

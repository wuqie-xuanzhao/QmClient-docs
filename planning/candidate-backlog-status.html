需要重写规格

主题为什么不能直接用旧清单建议下一步
UI 组件合并 / 动画统一 / Theme 系统范围过大，旧清单没有列出现有三套动画 helper 的真实调用面和风险。先读 qmui-consolidation-boundary-spec.html，再拆出一个重复 helper 或一个组件族，不直接做全局 UI 重构。
品牌化迁移 Qimeng -> QmClient涉及兼容性、配置域、文件名和用户数据迁移；旧清单把代码标识符和用户可见品牌混在一起。先读 brand-migration-boundary-spec.html 和 配置变量命名现状，分层处理 UI 文案、配置域、内部识别链路和远端服务。
网络卡顿诊断 / NetGraph / 性能监控面板已有 QmMonitoring、status bar 和设置页性能报表，旧清单未区分网络指标、渲染指标和设置页 trace。先读 network-diagnostics-panel-spec.html；后续只做状态栏诊断预设和只读解释，不新建平行 NetGraph 或自动调参。
Bind 指令系统化旧清单包含 m_vBinds、BindChat、Bindwheel、控制界面和配置文件多条线，范围过宽。先读 bind-systematization-boundary-spec.html；BindChat 管理 UI、BindWheel 快捷设置和配置包导出必须分开处理。
Workshop 浏览/上传涉及远端数据源、上传权限、内容审核和缓存，不是资源页 UI 小改；当前源码只有 catalog 浏览、下载、删除和本地作者缓存闭环。先读 workshop-upload-boundary.html，不直接在资源页实现上传。
本地跨局统计历史旧清单没有和 statboard CSV、PlayerStats HUD、中心服 playtime 分清边界。从 persistent-stats-status.html 拆一个“本地历史战绩 JSON 最小版”。
语音聊天当前已有 voice 子系统状态页；WebRTC/中心服重启方案已经按当前源码降级为历史想法。语音主线是 SDL + Opus + 自定义 UDP + 语音服务 /qm/*，不是中心服文本/Presence 小改。从 voice-chat-status.html 继续补真实双端、权限、热插拔和失败恢复验证，不从旧 TODO 重启方案。
Speedrun Timer / Media Background / Finish PredictionBC 移植项之间风险差异很大，不能在一个大任务里混做；Media Background 已确认底层视频背景存在但产品化管理仍缺，Finish Prediction 已确认不能和 Race Time、Speedrun Timer、Split Timer 或 Gores 进度混为一谈。从 bc-port-status.html、media-background-boundary.html 和 finish-prediction-boundary.html 拆成独立状态页或实现计划。

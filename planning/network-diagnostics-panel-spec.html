网络诊断面板与状态栏预设规格

本文把旧 “NetGraph / 网络卡顿诊断 / 性能监控面板” 想法收敛为一个后续小规格：复用已经存在的 CQmMonitoring 和 TClient 状态栏，补一层只读诊断解释与状态栏预设入口；不新建平行 NetGraph，不自动修改 AntiPing 或预测参数。

当前结论 目标与非目标 建议设计 验收边界 复核证据

当前结论

能力现状后续口径
QmMonitoring 指标已实现已有 latency、prediction、margin、jitter、resend loss、traffic、connection grade、primary cause、FPS/CPU/memory。
图形面板已实现dbg_graphs 打开时渲染 Qm monitoring HUD，不需要另起一个 NetGraph 面板。
状态栏已实现状态栏已有网络与性能条目，并有设置页编辑器；缺的是面向网络诊断的预设和解释。
性能日志已有链路qm_perf_* 适合做开发诊断，不应和玩家网络 HUD 混成一个功能。
自动调参不进入本规格预测和 AntiPing 参数属于玩法手感风险，不从诊断面板直接改。

目标与非目标

目标说明
只读诊断摘要把当前 EQmConnectionGrade 和 EQmDiagnosticCause 翻译成玩家能理解的短句，显示在已有 Qm monitoring HUD 或设置说明中。
状态栏诊断预设提供一键应用的 status bar scheme，例如 u n j k q，让玩家不用手填代码。
解释 resend loss明确 k 是 resend-based estimate，不是服务器权威丢包。
保留开发者入口dbg_graphs 仍是完整图表入口；普通状态栏只展示轻量指标。
非目标原因
新建第二套 NetGraph 渲染器当前 CQmMonitoring::RenderHud() 已有图形面板和历史曲线。
自动修改 cl_antiping_* 或 prediction margin风险见 adaptive-antiping-status.html；本规格只做诊断。
判断服务器权威卡顿原因客户端没有服务端帧耗时、队列拥塞和服务器 tick profiling 信号。
把 perf HTML 报表塞进游戏内 HUDperf 报表面向离线/开发分析，和玩家实时状态栏不是同一层。

建议设计

  1. 在 TClient 状态栏设置页增加 “Network diagnostics” 预设按钮，应用 u n j k q 或 u n j k i o q。
  2. 在预设旁边显示简短解释：snapshot latency、prediction latency、jitter、resend loss、connection quality。
  3. 在 Qm monitoring HUD header 或 debug details 中复用现有 grade/cause，显示当前主因，不新增采样字段。
  4. 把 “诊断建议” 保持为只读文本，例如 “Jitter high: check Wi-Fi / routing before changing AntiPing”。
  5. 如需更细的弱网建议，另写 Adaptive AntiPing 建议规格，不在本页自动落地。

最小闭环是“让玩家可以一键打开网络状态栏预设，并知道每个指标代表什么”。这比新增图表更贴近当前代码，也更容易验证。

验收边界

检查项应验证
状态栏预设点击后更新 tc_statusbar_scheme，并立即调用现有 ApplyStatusBarScheme() / UpdateStatusBarScheme()。
不新增采样路径所有显示数据来自 m_QmMonitoring.Snapshot() 或现有状态栏项。
不改预测配置变更 diff 中不得写入 cl_antiping_*、prediction margin 自动调整或类似配置。
文案边界清楚标注 resend loss 是估计值，connection quality 是客户端观察，不是服务器权威诊断。
UI 回归状态栏设置页预览、添加/删除条目、手动 scheme 编辑仍可用。

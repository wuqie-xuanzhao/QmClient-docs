Split Timer 检查点分段计时小规格

本页把 BC 未落地项 Split Timer 收敛为一个只读 HUD 小规格：基于当前 race time 和检查点事件记录本地分段时间，用于练图复盘；不改协议、不改预测、不写 demo 格式、不做自动成绩系统。

① 目标与非目标 ② 数据来源 ③ 状态模型 ④ HUD 与设置 ⑤ 验收 ⑥ 当前证据

① 目标与非目标

类型范围理由
目标在本地玩家经过 race checkpoint / tele checkpoint 类事件时记录当前 race time，显示最近分段差值。当前已有 race time、status bar race item 和 Speedrun Timer HUD，可复用计时口径。
目标只保留当前 run 的最近 N 个 split 和 best session 对比。P0 先服务练图即时反馈，不做跨图数据库。
暂不做跨局持久化 PB、排行榜、云同步、Kog 组队榜、成就。这些已属于统计/本地历史或远端服务方向。
暂不做自动 Finish Prediction、全地图路线识别、预测玩家未来完成时间。Finish Prediction 是另一个 BC 未落地项，风险和数据需求不同；边界见 finish-prediction-boundary.html。
禁止改协议、snapshot、物理、预测、碰撞、rank 可达性或 demo 文件格式。Split Timer 必须是客户端只读辅助，不影响玩法语义。

② 数据来源

来源P0 用法边界
Race time优先复用 CGameClient::CurrentRaceTime() 或和 status bar 一致的 GAMESTATEFLAG_RACETIME 计算。不要自己发明第二套计时基准。
Checkpoint 事件优先监听当前客户端已经收到的 race/checkpoint 相关消息或事件；如果无法稳定识别，P0 降级为手动 split 热键。不新增网络协议，不要求服务端发送新字段。
Run 重置race 未开始、重新开始、换图、离线、gameover 时清空当前 run splits。不跨地图继承状态。
Best session同一地图同一会话内保存最优 split 时间，用于显示 +/- 差值。P0 不写文件，避免隐私和存储边界扩大。

如果源码复核发现 checkpoint 事件没有可靠本地入口，不应硬做地图 tile 扫描或预测路径。先实现手动 split，或另写 checkpoint 事件调研。

③ 状态模型

  • CurrentRun：保存当前地图、race start tick、最近 checkpoint index、split 时间数组。
  • SessionBest：同一地图本客户端会话内的最佳 split 时间数组，换图或断线清空。
  • LastSplitPopup：最近一次 split 的增量时间、相对 best 的差值、显示到期 tick。
  • 重复 checkpoint index 在短时间内只记录一次，避免网络重复消息或回退误触发。
  • 如果 race time 回退或 LastRaceTick() 变化，当前 run 必须重置。

④ HUD 与设置

项规格默认
主开关qm_split_timer。关闭。
显示模式最近一次 split popup、右侧小列表、两者都显示。popup。
列表长度最近 3-10 个 split。5。
颜色快于 session best 用绿色，慢于 best 用橙/红，首次记录用中性色。跟随 HUD 透明度。
手动 split可选命令 qm_split_mark，用于无法识别 checkpoint 的地图或调试。P1 或 P0 降级项。

设置入口可以放在 QmClient 的 Speedrun Timer 模块附近，但文案必须区分：Speedrun Timer 是倒计时目标，Split Timer 是已发生分段记录。

⑤ 验收

检查项验收标准
功能本地 race 已开始后，触发 split 能显示当前分段、总 race time 和相对 session best 差值。
重置换图、重新开始、断线、gameover 或 race tick 变化时不会沿用上一轮 split。
兼容不影响现有 status bar race time、Speedrun Timer、DDNet race message 和 demo 播放。
边界没有 checkpoint 事件的地图不崩溃、不产生虚假 split；可降级到手动 split。
验证实现后至少跑文档 gate、quick gate 或本地手动 race/checkpoint 验证，并回填 BC 功能移植现状。

统计与持久化现状

本页接管旧 persistent-stats-plan.md。当前统计能力分成四条线：DDNet 局内 statboard、自动 CSV、Qm/TClient 当前会话 PlayerStats HUD、QmClient 中心服在线时长。旧案中的本地跨局战绩 JSON、历史趋势图和成就系统仍未实现。

当前已存在的能力

领域状态当前实现说明
局内 statboardimplementedCClientStats m_aStats[MAX_CLIENTS] 记录 frags、deaths、suicides、spree、weapon F/D、flag grabs/captures 和 ingame ticks。这是按当前局/当前玩家在线状态维护的数据，不是长期数据库。
局内重置implementedgame reset、round start 和玩家离开时会重置 m_aStats；进入/离开 spectator 会累加本局 ingame ticks。旧文档“每局重置”仍成立，但不是完整现状。
Statboard CSVimplementedFormatStats 输出服务器名、game type、map 和玩家统计；cl_auto_csv 游戏结束后写 CSV。这是导出快照，不是可查询历史记录。
自动 CSV 清理implemented with mismatchCSV 写入路径是 screenshots/auto/stats_*.csv，但清理逻辑使用 record/csv、autorecord、.csv。这是值得后续源码复核的 gap；本轮只记录，不改源码。
Qm PlayerStats HUDimplementedSPlayerStats 跟踪当前会话存活时间、救醒/冻结次数、左右出钩次数；HUD 显示 alive、rescue/freeze、hooking L/R。可配置进服重置；默认不是跨局历史战绩。
Gores 地图进度implementedqm_player_stats_map_progress* 控制地图进度条，可嵌入 HUD 或独立底部横条。这是当前地图进度可视化，不是统计趋势图。
中心服在线时长implementedCQmClient 使用 playtime/start、stop、query 同步总在线秒数，并本地保存 playtime_client_id.txt。它统计客户端在线时长，不统计每局 frags/deaths。
崩溃恢复 markerimplementedqmclient/lifecycle_pending.marker 记录 session、started_at、last_seen_at 和 client_id，用于异常退出恢复 stop 上报。这是 lifecycle/playtime 恢复机制，不是本地历史战绩。
历史战绩数据库not implemented本轮未看到 qmclient_stats.json、session stats vector、历史趋势图、按地图累计 frags/deaths 或成就系统。旧案这部分仍是规划。

建议下一版最小计划

优先级主题范围验收点
P0状态固定把四条统计线写清楚：statboard、CSV、PlayerStats HUD、playtime。后续不再把“在线时长持久化”误认为“战绩持久化已完成”。
P0自动 CSV 路径复核单独检查 screenshots/auto/stats_*.csv 写入路径与 record/csv/autorecord*.csv 清理路径是否不一致。确认是否是 bug；若是，另开源码修复任务。
P1本地历史最小版只记录本地玩家每次会话的 map、server、start/end、PlayerStats HUD 指标和 statboard 快照摘要。使用 QmClient sidecar 文件，不修改 demo/协议/服务端语义。
P1隐私和开关历史记录默认关闭或明确提示；player name、server name、map name 是否写入必须可控。用户能删除/禁用本地历史记录。
P2查询/导出先提供 CSV/JSON 导出和简单列表，不做图表库。不会引入复杂 UI 或长期性能负担。
P3趋势图有稳定历史数据后再做折线/柱状图。图表使用已有 UI 绘制能力，不引入大依赖。

截图管理与水印现状

本页接管旧 screenshot-manager-plan.md。当前 QmClient 已有截图保存、自动截图、截图动画和复用 Demo 浏览器的截图浏览/预览/打开/删除能力；旧文档中“缺少管理界面”的判断已不完整。

当前已存在的能力

领域状态当前实现说明
手动截图implemented控制台注册 screenshot 命令，默认按键绑定中 F10 触发截图。旧文档写 F12 不符合当前默认绑定。
保存路径与命名implementedTakeScreenshot 写入 screenshots/<name>_<timestamp>.png，普通截图名为 screenshot_*.png。当前文件名带时间戳，但不带地图名、服务器名或玩家名。
异步保存implemented截图帧数据采集后交给 CScreenshotSaveJob，由 job 调用 CImageLoader::SavePng 写盘。保存不是直接在 UI 代码中同步完成，但采集截图仍会等待渲染后端空闲。
截图动画implementedCGameClient::OnScreenshotTaken 触发 CUiEffects::StartScreenshotAnimation，显示截图缩略动画。旧文档没有覆盖当前截图反馈效果。
自动截图implementedcl_auto_screenshot 和 cl_auto_statboard_screenshot 支持游戏结束截图和统计板截图，并可限制自动截图数量。当前已有 screenshots/auto 与 screenshots/auto/stats 目录。
截图浏览入口implementedDemo 浏览器可在 Replay 和 Screenshots 间切换，截图模式浏览 screenshots 目录。这已经是游戏内截图管理入口，不应再说完全没有管理界面。
截图预览implemented截图模式支持 PNG/WebP 预览，列表支持 PNG/JPG/JPEG/WebP 文件。JPG/JPEG 当前列入列表，但本轮看到预览加载覆盖 PNG/WebP。
打开/删除/重命名implemented截图模式可打开截图文件、打开截图目录、删除截图，并复用 Demo 浏览器重命名弹窗文案。仍未看到“复制图片到剪贴板”或上传分享链路。

旧计划修正

旧计划点当前判断处理方式
当前只有基础截图，缺少游戏内浏览截图。已过时当前 Demo 浏览器已有 Screenshots 模式、列表、预览、打开目录、打开文件、删除和重命名入口。
默认截图快捷键是 F12。错误当前默认绑定中截图是 F10，命令仍是 screenshot。
文件名不含游戏信息。部分成立当前含时间戳，但不含地图名、服务器名、玩家名或自定义前缀。
水印、时间戳/地图名叠加。仍是规划当前未看到截图水印配置或保存前叠加渲染流程；可作为后续最小功能。
一键分享、上传图床。仍是规划当前可以打开文件或目录，但未看到图片剪贴板、上传服务或分享 URL。
新增 cl_screenshot_* 配置。命名需重写QmClient 新增配置应优先使用 qm_ / Qm 前缀；现有上游截图配置仍保留 cl_auto_*。

建议下一版最小计划

优先级主题范围验收点
P0状态固定把“截图已纳入 Demo 浏览器 Screenshots 模式”写入当前文档，旧计划标记为 superseded。后续不会再按“从零做截图管理器”立项。
P1截图水印最小版仅支持截图时叠加 QmClient 标识、时间和地图名，不做上传、不做复杂模板。开关默认关闭；配置使用 qm_ 前缀；普通截图和自动截图行为可预测。
P1文件命名增强允许可选地在文件名前缀中加入地图名，必须做路径字符清理和长度限制。不破坏现有 screenshots/screenshot_*.png 和自动截图清理规则。
P2图片剪贴板先调研 SDL/平台支持，不直接引入上传服务。失败时保留打开文件/目录路径，不阻塞截图浏览。
P3上传分享只有在隐私、网络错误、鉴权和服务选择明确后再做。默认不自动上传，不把第三方图床做成核心依赖。

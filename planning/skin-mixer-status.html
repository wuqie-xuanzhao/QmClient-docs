皮肤混搭与资源编辑现状

本页接管旧 skin-mixer-plan.md。当前 QmClient 没有旧案描述的运行时 .qmixin 混搭配置、分享码或独立 Skin Mixer profile；但资源页资产编辑器已经支持 Skin 类型的 Frankenstein 部件拖拽、染色、预览和导出。

当前已存在的能力

领域状态当前实现说明
皮肤 ProfileimplementedCSkinProfiles 保存皮肤名、body/feet 颜色、旗帜、默认表情、名字和 clan，并写入 QmClient/qmclient_profiles.cfg。这是 Tee profile，不是部件混搭配置。
Profile UIimplementedTClient Profiles 页面支持保存、加载、删除、覆盖，并可选择是否保存/加载 Skin、Colors、Emote、Name、Clan、Flag。旧文档提到的“皮肤配置文件”存在，但路径在 components/tclient/，不是 components/qmclient/。
资源页 Skin 编辑器implemented资源设置页可打开 ASSETS_EDITOR_TYPE_SKIN，编辑器左侧是 donor，右侧是 Frankenstein 画布。这是当前最接近“皮肤混搭”的实现。
部件拖拽混搭implementedSkin 编辑器通过 SAssetsEditorPartSlot 跟踪目标区域、来源 asset、源区域和 tint；拖拽左侧部件到右侧可替换单个或同族同尺寸部件。旧案中“无法混搭部位”已不符合资源编辑器现状。
部件染色implemented编辑器支持点击 Frankenstein 部件调整颜色，合成时按 blend mode 把颜色覆盖应用到对应图像区域。这是资源图像染色，不等同于运行时 body/feet 自定义颜色。
导出格式implementedSkin 导出会写 skins/<name>.png、skins7/body/<name>.png、skins7/feet/<name>.png、skins7/hands/<name>.png 和 skins7/<name>.json。导出后刷新 skin 列表，产物是标准 skin/skins7 资源，而不是独立混搭配置。
分享码 / Workshop 上传not implemented本轮未看到 .qmixin、分享码、混搭 JSON sidecar 或一键上传 Workshop 的实现。旧案这部分仍是未规格化规划。

旧计划修正

旧计划点当前判断处理方式
无法混搭部位。已过时资源页 Skin 资产编辑器已经支持 donor -> Frankenstein 部件替换和预览。
缺少实时预览。已过时资产编辑器有 composed preview texture，并在修改后刷新预览。
缺少保存。部分过时当前可以导出成标准 skin/skins7 文件；但没有保存“可继续编辑的混搭配方”。
扩展 components/qmclient/skinprofiles.*。路径错误当前 profile 代码在 src/game/client/components/tclient/skinprofiles.*。
新增 qm_skin_mixer 开关。不建议直接做当前混搭作为资源编辑器工具存在，不需要先加运行时总开关。若未来新增配置，应先明确它控制编辑器、导出还是运行时皮肤选择。
导出 .qmixin / 分享码 / Workshop 上传。仍是规划这会引入新格式和兼容问题；先不要替代现有标准 skin/skins7 导出。

建议下一版最小计划

优先级主题范围验收点
P0状态固定把旧“无法混搭/无预览/无保存”改为“资源编辑器已有一次性 Frankenstein 导出”。后续不再按从零实现 Skin Mixer 立项。
P1编辑器说明补用户文档说明 Skin 编辑器入口、donor/Frankenstein 概念、拖拽、染色、Reset All 和 Export。用户能找到并使用当前能力，不需要新增源码。
P1可编辑配方如果确实需要持续编辑混搭结果，先设计 sidecar recipe，不改变已导出的标准 skin 文件语义。标准 DDNet/QmClient 皮肤加载仍可不依赖 sidecar。
P2Profile 联动只在导出 skin 后复用现有 Tee profile 保存皮肤名和颜色；不要把 profile 结构变成部件配方存储。qmclient_profiles.cfg 继续保持当前命令式格式。
P3分享/Workshop先支持打开导出目录或复制说明；一键上传需要单独处理鉴权、失败恢复和版权提示。不把第三方分享链路作为基础混搭能力依赖。

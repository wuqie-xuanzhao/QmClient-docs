Demo/观战导演目标推荐小规格

本页把 Demo/观战导演方向收敛为一个不触碰画中画、不改 demo 格式、不做全自动高光评分的小规格：基于现有 LiveDirector / MultiView / live observer overlay，提供可解释的观战目标推荐和手动确认切换。

① 目标与非目标 ② 推荐信号 ③ 切换规则 ④ UI 与配置 ⑤ 验收 ⑥ 当前证据

① 目标与非目标

类型范围理由
目标在 live observer / director 路径中给出下一个推荐观战目标。当前已有队伍/玩家 entries、随机选择和 fallback，适合先做可解释推荐。
目标推荐理由必须可显示，例如“同队领先”“接近 finish”“活跃移动”。避免黑盒自动切换干扰观战者。
目标默认手动确认切换，可选自动切换。先保证可控性，再讨论自动导演。
暂不做画中画 UI、视频导出、全自动精彩度评分、跨玩法高光系统。新版 TODO 已否决画中画；高光评分需要单独事件来源设计。
禁止修改 demo 文件格式、网络协议、预测或玩法语义。本规格只使用客户端已有可见状态做观战辅助。

② 推荐信号

信号P1 是否使用说明
LiveDirector team/player entries使用已有结构能枚举可观战队伍和玩家，是推荐的基础。
当前观战目标/自由视角使用避免重复推荐当前目标；自由视角下优先给明确候选。
玩家活跃度轻量使用只用位置变化、存活/冻结等本地可见状态，不引入复杂评分。
Gores map progress可选只在已有距离/进度数据可用时使用，不能作为通用 DDRace 评分。
击杀、夺旗、PB、Finish 高光不使用不同玩法事件来源不同，P1 不混做。

③ 切换规则

  • 推荐候选必须来自当前可观战玩家或队伍，不推荐无效 client id。
  • 推荐理由最多保留 1-2 个，避免 UI 像调试日志。
  • 手动确认模式下，只显示“推荐切换到 X”，不自动调用 spectate。
  • 自动模式必须有冷却时间，避免玩家目标频繁跳变。
  • 当前目标仍有效且没有更强理由时，不抢切。
  • 无法计算推荐时回退到现有随机/默认 director 行为。

④ UI 与配置

项目建议说明
入口Live observer overlay 附近不新建大型 Demo 面板。
默认模式推荐提示 + 手动确认避免用户误以为客户端自动接管观战。
自动切换可选开关，默认关闭后续再评估是否适合直播/录制场景。
配置命名qm_director_recommend_*QmClient 新配置使用 qm_ 前缀。
日志可选 debug记录推荐理由用于调参，但默认不刷屏。

⑤ 验收

检查项验收标准
默认兼容关闭推荐功能时，LiveDirector、MultiView、Demo 播放和观战行为不变。
推荐有效性推荐目标始终是当前有效可观战玩家或队伍。
可解释UI 能显示推荐目标和简短理由。
防抖自动模式有冷却，不会连续频繁切换。
边界无候选、目标离开、队伍消失、Demo 播放状态下不崩溃。
验证记录实现后回填 demo-spectator-status.html 和 innovation-roadmap.html。

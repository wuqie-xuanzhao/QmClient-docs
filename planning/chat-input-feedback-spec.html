聊天输入与消息行反馈小规格

本页把“聊天框 UI 增强”收敛成一个可实施的小范围规格：只补输入框焦点/状态反馈和消息行 hover/命中反馈，不重写聊天系统、不迁移消息区到 QmUi 动画运行时。

① 目标与非目标 ② 输入框反馈 ③ 消息行反馈 ④ 交互规则 ⑤ 验收 ⑥ 当前证据

① 目标与非目标

类型范围理由
目标聊天打开时，让输入框有稳定背景、边框、焦点态和翻译按钮状态反馈。当前输入框已有发送、补全、草稿、翻译按钮和命令预览，适合做轻量视觉收口。
目标聊天激活时，让鼠标 hover 的消息行有低干扰高亮，并能提示左键复制、右键菜单。当前复制/右键菜单已经存在，但命中区域不够可见。
暂不做历史搜索、表情面板、逐条翻译按钮、消息工具条。这些是新功能入口，不属于“反馈补齐”。
暂不做把消息区迁移到 CUiV2AnimationRuntime。会触碰渲染、命中、backlog 可见性和性能预算，应另写重构规格。
禁止改变聊天发送、补全、输入法、草稿保存、翻译发送链路、复制和右键菜单语义。本规格是表现层增强，不能改变既有行为。

② 输入框反馈

元素期望状态实现边界
输入框背景聊天打开时显示半透明背景和 1px 边框，团队/全体/私聊模式可以用轻微色调区分。只在 m_Mode != MODE_NONE 时绘制，不新增复杂主题系统。
焦点态输入激活时边框更清晰，命令输入 / 时可用弱提示色区分。不能遮挡命令预览、输入文本、候选补全和输入法组合文本。
翻译按钮保持现有语言图标，hover、按下、自动出站开启/关闭状态更容易区分。复用当前 qm_translate_btn_color_* 和 tooltip；不新增 qm_translate_show_button。
字符/长度反馈只在接近输入上限时显示紧凑计数或警示，不常驻占用空间。如果当前输入组件无法可靠暴露剩余长度，可降级为后续。

③ 消息行反馈

元素期望状态实现边界
hover 高亮聊天激活、鼠标停在可复制文本行上时显示低透明背景或侧边短线。只对当前已有命中区域生效，不扩大到输入框、滚动条和翻译按钮。
按下反馈左键按下到释放前给轻微状态差异，释放后仍按当前逻辑复制。拖动超过 IsCopyClickDrag() 阈值时不能误触复制。
右键入口提示hover 时可以显示非常克制的菜单提示符或仅通过 tooltip 表达。不新增常驻行尾按钮，避免遮挡聊天文本和旧版聊天布局。
旧版聊天cl_chat_old 路径不被破坏。如果旧版布局没有稳定行矩形，默认不显示新 hover 背景。

④ 交互规则

  • 所有反馈都必须依赖当前命中检测，不创建第二套复制/右键命中规则。
  • 语言菜单或聊天行菜单打开时，不显示新的 hover 操作提示，避免和 popup 焦点冲突。
  • 输入框反馈不能改变 m_Input.ProcessInput()、历史上下键、Tab 补全、BindChat 和 TClient spec id 处理。
  • 视觉强度必须低于聊天文本本身，默认不使用大面积高饱和背景。
  • 如果需要配置，使用 qm_ 前缀；P0 建议不新增配置，先跟随现有聊天可见性开关。

⑤ 验收

检查项验收标准
输入行为发送普通聊天、团队聊天、命令、补全、滚轮历史和草稿保留与修改前一致。
翻译按钮左键菜单、右键自动出站翻译、hover tooltip 和菜单定位不回归。
消息行左键复制、右键菜单、滚动条拖动、输入框选择和旧版聊天模式不互相干扰。
视觉不同聊天缩放、普通 HUD、HUD editor 预览和 16:9/窄屏下没有文字遮挡。
验证实现后至少跑文档 gate、相关 quick gate 或手动 UI 截图检查，并把结果写回 聊天框 UI 增强现状。

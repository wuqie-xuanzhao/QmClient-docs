QmClient 语音聊天现状

本文以当前源码为准，替代旧版围绕 Rust 语音模块、平铺文件路径和早期测试缺口的调研口径。当前主实现是 src/game/client/components/qmclient/voice/ 下的 C++ 语音子系统。

当前结论 架构与文件边界 运行时线程模型 协议与房间边界 WebRTC / 中心服旧案边界 配置与 UI 测试覆盖 旧报告修正 复核证据

当前结论

  • 当前有效 语音模块是纯 C++ 运行路径：组件入口 CVoiceComponent 只持有 CRClientVoice m_Voice，没有 Rust/C++ 双运行时切换成员。
  • 当前有效 功能链路包含 SDL 音频设备、Opus 编解码、自定义 UDP 包头、PTT/VAD/本地测试/服务器回环、空间音频、名单过滤、房间 Token 和说话叠加层。
  • 当前有效 当前源码未见 WebRTC 语音实现或 WebRTC 构建入口；旧 backlog 中“考虑使用 WebRTC 或其他语音库”的说法应降级为历史想法，不作为下一步默认方案。
  • 当前有效 捕获处理已经拆到 voice_capture_pipeline，顺序为 AGC 增益、麦克风增益、降噪、HPF/压缩/限幅。
  • 仍需外部验证 单元测试覆盖了协议、状态 helper、设备提示、降噪默认值和 capture pipeline 顺序，但真实双端互听、真设备热插拔和系统权限弹窗仍属于集成/真机验证。

架构与文件边界

文件当前职责文档口径
voice_component.h/.cpp组件生命周期、控制台命令、开关驱动、叠加层状态导出与 HUD editor preview 渲染。入口层，不再使用旧文档的平铺路径。
voice_core.h/.cpp语音运行时主体：socket、SDL 设备、worker、Opus、jitter、混音、配置快照、UI 状态导出。核心维护面。
voice_capture_pipeline.h/.cpp采集帧处理：AGC、麦克风增益、简单降噪/RNNoise、HPF、压缩、限幅。旧报告缺失，应作为当前主链路记录。
voice_utils.h/.cpp协议读写、包分类、token/group 规则、设备下拉 helper、状态文案 helper、音频数学辅助。测试覆盖的主要工具层。
qmclient.cpp / qmclient_utils.*Qm 标识、在线分布、voice_supported 标记和 /qm/* JSON 解析。不是 PCM/UDP 媒体本体，但会影响用户对语音可用性的感知。

旧 Markdown 中的 src/game/client/components/qmclient/voice_component.*、voice_core.* 平铺路径已经不适合作为当前入口。

运行时线程模型

线程/阶段职责关键边界
主线程CVoiceComponent::OnRender() 在 qm_voice_enable 开启时调用 m_Voice.OnFrame()；关闭时 shutdown 并清空 overlay。主线程负责配置/客户端快照和请求态锁存，不直接在 worker 中读取 live 设备配置。
worker 线程WorkerLoop() 轮询音频重建、服务端解析、收包、jitter 解码、编码参数更新和采集发送。循环末尾约 5ms sleep；设备失败会按重试间隔重新 EnsureAudio。
SDL 输出回调SDLAudioCallback 调用 MixAudio() 从各 peer 解码帧混音。输出缓冲复用 m_MixBuffer，避免每次回调临时分配。
采集处理ProcessCapture() 从 SDL capture 队列取 960 samples 帧，处理后按 PTT/VAD/test mode 决定发送或本地回放。本地测试模式不需要网络；服务器回环会设置 loopback flag。

协议与房间边界

当前语音协议常量为 VOICE_VERSION = 3，魔数为 RV01，固定包头包含版本、类型、payload 大小、context hash、token hash、flags、sender id、sequence 和发送者位置。包类型分为 AUDIO、PING、PONG。

边界当前行为
context接收侧按 m_ContextHash 过滤当前游戏/服务上下文，context 不一致直接丢弃。
房间 tokenBuildLegacyVoiceTokenHash() 仍以 room token hash 为基础；VoiceTokenGroupHash() 使用低 30 位做 group 兼容判断。
keepalivetoken 变化或空闲超过约 2 秒会发送 PING；匹配 outstanding ping 时更新 RTT。
可听性音频包在进入 jitter 前还会经过 self、active/spec、team visibility、mute/white/black list、VAD allow、距离半径和全图收听规则。
Qm 同步/qm/token、/qm/report、/qm/users.json 位于语音服务 host:port 的 /qm/* 命名空间；中心服务 :8080 不使用该前缀。

WebRTC / 中心服旧案边界

旧 backlog 的“考虑使用 WebRTC 或其他语音库”不应继续作为当前默认路线。当前语音系统已经是 SDL 采集/播放、Opus 编解码、自定义 UDP 包头和语音服务 host:port 组合；迁移到 WebRTC 会变成一次新的音频网络架构设计，而不是整理现有语音功能。

旧想法当前事实处理口径
改用 WebRTC。本轮在 src/game/client/components/qmclient/、config_variables_qmclient.h、CMakeLists.txt 和 cmake/ 未见 WebRTC 语音实现或构建开关。不作为默认后续 除非另写新架构调研，不能从旧 TODO 直接开工。
依赖中心服做语音聊天。当前 /qm/token、/qm/report、/qm/users.json 使用语音服务 host:port 下的 /qm/* 路由；中心服务 :8080 不承载该命名空间。已拆清 调试时区分媒体面、语音服务 /qm/* 和中心服识别。
从零做语音系统。CMake 已编入 voice_capture_pipeline、voice_component、voice_core、voice_utils，测试侧也编入相关工具层。已过时 后续应先补真实环境验证、状态文案和失败恢复，不重建主链路。

配置与 UI

配置项集中在 config_variables_qmclient.h，统一使用 QmVoice* / qm_voice_* 前缀。默认语音关闭，默认服务端为 42.194.185.210:9987，默认协议版本为 3。

区域当前状态
降噪/动态处理qm_voice_noise_suppress_enable 是三态：0 关闭、1 简单、2 RNNoise；默认 2。默认强度 35，压缩阈值 24%，ratio 2.0，attack 12ms，release 140ms，makeup 125%，limiter 92%。
控制方式支持 +qm_voice_ptt、VAD、PTT release delay、本地测试模式和服务器回环测试模式。
设备设置页提供输入/输出设备下拉、刷新按钮、默认设备、断开设备回显和切换中/已切换/失败状态。
状态面板高级选项中可展示麦克风、扬声器、输入切换、输出切换、服务器、房间、收发、排障建议、音频问题和详细原因。
叠加层CVoiceOverlayState 记录最近听到/本地发声者，HUD editor 中无真实条目时会绘制 preview。

测试覆盖

  • 协议层：读写 U16/U32/float、RV01 固定向量、AUDIO/PING/PONG 分类、payload 长度、版本/类型/context/group/sender/drop 分支。
  • 房间与收发规则：legacy/mode packed token 兼容、keepalive token 不同组拒绝、PING RTT 前置条件、jitter 起始序列和 wrap-around。
  • UI 状态：麦克风/扬声器/服务器/房间/收发状态、排障建议、权限拒绝、设备不存在、输入/输出路由切换状态。
  • 音频处理：默认降噪/压缩参数与配置一致、trace callback、capture pipeline 顺序、手动码率档位、网络质量下的编码复杂度调整。
  • Qm 同步：users.json 中 server_address|server、player_id|id、voice_supported 和本服 marks 聚合规则。

测试不等价于完整语音可用性闭环。真实双客户端、真实语音服务、OS 权限弹窗、耳机热插拔和默认路由漂移仍需要人工或集成环境补位。

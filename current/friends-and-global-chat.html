QmClient 好友分类与全局聊天现状

本文接管旧版“好友分类与全局聊天功能报告”：好友分类、备注、持久化和 Qm 好友提醒是当前实现；跨服务器全局聊天没有实现，边界调研见 global-chat-boundary-spec.html。

当前结论

能力状态维护口径
好友分类、备注、持久化已实现IFriends / CFriends 已提供分类增删改、排序、好友归类、备注和配置保存。
Qm 好友上线提醒已实现基于服务器浏览器 HTTP 列表扫描，不是账号在线状态服务。
Qm 好友进服问候/播报已实现只检测当前服务器内好友进入，支持大字播报和延迟自动问候。
跨服务器全局聊天未实现未发现独立 socket、协议、服务端或 GlobalChat 组件；继续作为 高风险边界调研项。

代码中的 Team=0 global 表示当前服务器内的全服聊天，不等于跨服务器全局聊天。

好友分类能力

好友模型仍以名称和战队为识别基础，单条好友记录包含 name、clan、category、note 和 hash。上限为 4096 个好友、64 个分类，分类名和备注长度分别由 MAX_FRIEND_CATEGORY_LENGTH、MAX_FRIEND_NOTE_LENGTH 控制。

功能入口/接口当前行为
新增分类friend_category_add / AddCategory()会规范化分类名，拒绝受保护分类和重复项；新增分类插入到 Offline 之前。
移动分类MoveCategory()支持分类排序，移动的是分类数组位置，不重写好友身份。
重命名分类friend_category_rename / RenameCategory()重命名后会同步更新属于旧分类的好友记录。
删除分类friend_category_remove / RemoveCategory()删除非受保护分类时，成员会回落到默认分类。
设置好友分类set_friend_category / SetFriendCategory()只能设为已存在分类，不能手动设为 Clan Members。
好友备注set_friend_note / clear_friend_note备注写在好友记录里，并随配置保存。
配置保存ConfigSaveCallback()写出自定义分类、好友分类参数和备注，重启后可恢复。

预置分类当前是英文常量："Friends"、"Clan Members"、"Offline"。旧文档写成“好友 / 战队成员 / 离线”不是当前代码事实。

Qm 好友通知

配置状态边界
qm_friend_online_notify已实现启用后扫描服务器列表，发现好友在线时向本地聊天输出提示。
qm_friend_online_auto_refresh已实现可自动刷新服务器列表；刷新间隔至少 5 秒。
qm_friend_online_refresh_seconds已实现控制自动刷新间隔，配置范围为 5 到 300 秒。
qm_friend_enter_auto_greet已实现好友进入当前服务器后，延迟发送配置文本到当前服务器聊天。
qm_friend_enter_broadcast已实现好友进入当前服务器时显示大字提示。
qm_friend_enter_*_text已实现用于配置大字提示和自动问候文本。

这些能力是客户端侧体验增强：上线提醒依赖服务器浏览器列表，进服问候依赖当前服务器玩家列表。它们不是跨服聊天、账号系统或中心化 presence 服务。

全局聊天边界

  • 当前聊天发送接口是 CChat::SendChat(int Team, const char *pLine)，消息发送到当前服务器连接。
  • chat.cpp 注释里的 0 = global 指服务器内全服频道，和 1 = team、whisper 类型并列。
  • 未发现跨服务器聊天专用组件、网络通道、服务端协议或独立持久连接。
  • 语音系统里的 QmVoiceGroupGlobal 是语音房间/全图收听语义，不是文本跨服聊天。

如果要推进真正的全局聊天，需要先明确账号/身份、中心服务、协议、滥用控制、隐私与服务器兼容性边界；不能沿用当前服务器内聊天接口直接实现。详细边界见 跨服务器全局聊天边界调研。
